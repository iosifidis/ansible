# 4.4 Επαλήθευση εγκατάστασης ✅

## Γιατί είναι σημαντική η επαλήθευση;

Δεν αρκεί να τρέξει η εγκατάσταση χωρίς σφάλματα. Πρέπει να **επιβεβαιώσουμε** ότι:

```
✅ Η σωστή έκδοση Ansible εγκαταστάθηκε
✅ Χρησιμοποιείται το σωστό Python (από το venv)
✅ Διαβάζεται το σωστό ansible.cfg
✅ Η Ansible μπορεί να συνδεθεί σε servers
✅ Τα collections είναι διαθέσιμα
```

---

## Βήμα 1: `ansible --version`

Η πιο βασική εντολή επαλήθευσης:

```bash
ansible --version
```

### Αναμενόμενο Output και επεξήγηση:

```bash
ansible [core 2.20.4]          # ← έκδοση Ansible core
  config file = /home/ansible/ansible/ansible.cfg  
  # ↑ διαβάζει το ΔΙΚΟ ΜΑΣ ansible.cfg ✅
  # αν έλεγε "None" → πρόβλημα!

  configured module search path = ['/home/ansible/.ansible/plugins/modules']
  # ↑ πού ψάχνει για modules

  ansible python module location = /home/ansible/ansible/venv/lib/python3.13/site-packages/ansible
  # ↑ ΠΡΕΠΕΙ να δείχνει μέσα στο venv/ ✅

  ansible collection location = /home/ansible/.ansible/collections
  # ↑ πού αποθηκεύονται τα collections

  executable location = /home/ansible/ansible/venv/bin/ansible
  # ↑ ΚΡΙΣΙΜΟ: πρέπει να δείχνει venv/bin/ ✅
  # αν έλεγε /usr/bin/ansible → χρησιμοποιεί το system ansible!

  python version = 3.13.5 [GCC 14.2.0] (/home/ansible/ansible/venv/bin/python3)
  # ↑ ΚΡΙΣΙΜΟ: το python πρέπει να είναι από το venv/ ✅

  jinja version = 3.1.6
  # ↑ έκδοση Jinja2 (template engine)

  pyyaml version = 6.0.3 (with libyaml v0.2.5)
  # ↑ libyaml = True → γρήγορη επεξεργασία YAML ✅
```

### Τι να ελέγξεις:

```
✅ executable location → .../venv/bin/ansible
✅ python version      → .../venv/bin/python3
✅ config file         → το δικό σου ansible.cfg
✅ libyaml             → v0.x.x (όχι False)
```

## Βήμα 2: Έλεγχος Python Path

```bash
# Επιβεβαίωση ότι χρησιμοποιούμε το Python του venv
which python3
# /home/ansible/ansible/venv/bin/python3 ✅

which ansible
# /home/ansible/ansible/venv/bin/ansible ✅

which pip
# /home/ansible/ansible/venv/bin/pip ✅
```

> ⚠️ **Αν δεις `/usr/bin/python3` ή `/usr/bin/ansible`:**
> Σημαίνει ότι το venv δεν είναι ενεργοποιημένο!
```bash
source ~/ansible/venv/bin/activate
# και ξαναδοκίμασε
```

## Βήμα 4: Ping Test στο localhost

```bash
# Από τον φάκελο ~/ansible
cd ~/ansible

# Ping στο localhost
ansible localhost -m ansible.builtin.ping

# Αναμενόμενο output:
# localhost | SUCCESS => {
#     "changed": false,
#     "ping": "pong"     ← ✅
# }
```

---

## Βήμα 5: Ping Test σε Remote Server

```bash
# Ping σε όλους τους servers του inventory
ansible all -m ansible.builtin.ping

# Ping σε συγκεκριμένο server
ansible nextcloudpi -m ansible.builtin.ping

# Αναμενόμενο output:
# nextcloudpi | SUCCESS => {
#     "changed": false,
#     "ping": "pong"    ← ✅
# }
```

## Βήμα 6: Gathering Facts Test

Ελέγχουμε αν η Ansible μπορεί να **συλλέξει πληροφορίες** από τον server:

```bash
# Συλλογή facts από τον nextcloudpi
ansible nextcloudpi -m ansible.builtin.setup \
    -a "filter=ansible_distribution*"

# Αναμενόμενο output:
# nextcloudpi | SUCCESS => {
#     "ansible_facts": {
#         "ansible_distribution": "Debian",
#         "ansible_distribution_major_version": "12",
#         "ansible_distribution_release": "bookworm",
#         "ansible_distribution_version": "12.13"
#     },
#     "changed": false
# }
```

## Βήμα 7: Ad-hoc Command Test

```bash
# Τρέξε μια απλή εντολή σε όλους τους servers
ansible all -m ansible.builtin.command -a "uptime"

# Με sudo
ansible all -m ansible.builtin.command \
    -a "cat /etc/os-release" \
    --become

# Έλεγχος Python version στους remote servers
ansible all -m ansible.builtin.command \
    -a "python3 --version"
```
