# 4.2 Μέθοδοι εγκατάστασης Ansible 🔧

## Οι τρεις μέθοδοι

Όπως αναφέραμε στο Κεφάλαιο 3, υπάρχουν τρεις τρόποι εγκατάστασης. Εδώ θα τους αναλύσουμε **πλήρως** ώστε να καταλαβαίνεις πότε και γιατί να χρησιμοποιείς τον καθένα.

```
┌─────────────────────────────────────────────────────┐
│  Μέθοδος 1: OS Package Manager                      │
│  apt / dnf / zypper                                 │
├─────────────────────────────────────────────────────┤
│  Μέθοδος 2: pip + venv           ← ΣΥΝΙΣΤΑΤΑΙ       │
│  Python Virtual Environment                         │
├─────────────────────────────────────────────────────┤
│  Μέθοδος 3: pipx                                    │
│  Isolated Application Installer                     │
└─────────────────────────────────────────────────────┘
```

---

## Μέθοδος 1: OS Package Manager

Η πιο απλή μέθοδος — χρησιμοποιείς τον package manager της διανομής σου.

### Debian/Ubuntu:
```bash
sudo apt update
sudo apt install ansible -y

# Επαλήθευση
ansible --version
# ansible [core 2.14.x]  ← συχνά παλιά έκδοση!
# executable location = /usr/bin/ansible
```

### RedHat/Fedora:
```bash
# Fedora
sudo dnf install ansible -y

# Rocky/AlmaLinux (χρειάζεται EPEL)
sudo dnf install epel-release -y
sudo dnf install ansible -y

# Επαλήθευση
ansible --version
```

### openSUSE:
```bash
sudo zypper install ansible -y

# Επαλήθευση
ansible --version
```

### ✅ Πλεονεκτήματα:
```
✅ Απλό — μία εντολή
✅ Διαχειρίζεται αυτόματα τις εξαρτήσεις
✅ Ενημερώσεις μέσω system updates
✅ Καλό για servers που δεν χρειάζονται νέα features
```

### ❌ Μειονεκτήματα:
```
❌ Συχνά παλιά έκδοση Ansible
❌ Δεν ελέγχεις ποια έκδοση εγκαθίσταται
❌ Μπορεί να συγκρουστεί με άλλα Python packages
❌ Διαφορετική έκδοση σε κάθε διανομή → inconsistency
```

> ⚠️ **Πότε να το αποφύγεις:** Αν χρειάζεσαι **συγκεκριμένη έκδοση** Ansible ή τα **τελευταία features**, ο OS package manager δεν είναι η κατάλληλη επιλογή.

## Μέθοδος 2: pip + venv ← ΣΥΝΙΣΤΑΤΑΙ

Αυτή είναι η **επίσημα συνιστώμενη μέθοδος** από το Ansible project.

### Τι είναι το Virtual Environment (venv);

```
┌─────────────────────────────────────────────────────┐
│              Python System                          │
│  /usr/bin/python3                                   │
│  /usr/lib/python3/                                  │
│                                                     │
│  ┌───────────────────────────────────────────────┐  │
│  │         Virtual Environment (venv)            │  │
│  │  ~/ansible/venv/                              │  │
│  │  ├── bin/python3    ← απομονωμένο Python      │  │
│  │  ├── bin/pip        ← απομονωμένο pip         │  │
│  │  ├── bin/ansible    ← η Ansible μας           │  │
│  │  └── lib/           ← απομονωμένα packages    │  │
│  └───────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────┘
```

Το venv δημιουργεί ένα **απομονωμένο περιβάλλον** Python όπου:
- Εγκαθιστάς packages **χωρίς** να επηρεάζεις το σύστημα
- Έχεις **πλήρη έλεγχο** των εκδόσεων
- Μπορείς να έχεις **πολλά venvs** με διαφορετικές εκδόσεις

### Δημιουργία και χρήση venv:
```bash
# Δημιουργία venv
python3 -m venv ~/ansible/venv

# Ενεργοποίηση
source ~/ansible/venv/bin/activate
# (venv) user@host:~$  ← το (venv) δείχνει ότι είσαι μέσα

# Εγκατάσταση Ansible
pip install --upgrade pip
pip install ansible

# Απενεργοποίηση (όταν τελειώσεις)
deactivate
```

### ✅ Πλεονεκτήματα:
```
✅ Πάντα η τελευταία έκδοση Ansible
✅ Πλήρης έλεγχος εκδόσεων
✅ Απομόνωση από το σύστημα
✅ Εύκολη εγκατάσταση extra Python libraries
✅ Ίδια διαδικασία σε ΟΛΕΣ τις διανομές
✅ Εύκολη αφαίρεση (διαγράφεις τον φάκελο venv/)
✅ Ιδανικό για εκμάθηση — βλέπεις τι γίνεται
```

### ❌ Μειονεκτήματα:
```
❌ Χρειάζεται manual activation (λύνεται με .bashrc)
❌ Λίγο πιο σύνθετο από apt install
```

## Μέθοδος 3: pipx

Το **pipx** είναι ένα εργαλείο που κάνει αυτόματα αυτό που κάνουμε χειροκίνητα με το venv — αλλά **μόνο για εφαρμογές command-line**.

### Εγκατάσταση pipx:
```bash
# Debian/Ubuntu
sudo apt install pipx -y
pipx ensurepath

# RedHat/Fedora
sudo dnf install pipx -y
pipx ensurepath

# openSUSE
sudo zypper install python3-pipx -y
pipx ensurepath
```

### Εγκατάσταση Ansible με pipx:
```bash
# Μία εντολή — αυτόματα φτιάχνει venv και εγκαθιστά
pipx install ansible

# Επαλήθευση
ansible --version
# executable location = /home/user/.local/bin/ansible ✅
```

### Εγκατάσταση extra Python libraries με pipx:
```bash
# Αν χρειαστείς επιπλέον libraries (π.χ. boto3 για AWS)
pipx inject ansible boto3
```

### ✅ Πλεονεκτήματα:
```
✅ Απλό — μία εντολή
✅ Αυτόματο isolation (venv κάτω από την κουβέρτα)
✅ Αυτόματη προσθήκη στο PATH
✅ Εύκολη αναβάθμιση: pipx upgrade ansible
✅ Ιδανικό για έμπειρους χρήστες
```

### ❌ Μειονεκτήματα:
```
❌ Δεν βλέπεις τι γίνεται "κάτω από την κουβέρτα"
❌ Λιγότερος έλεγχος του environment
❌ Δύσκολο για εκμάθηση
❌ Περιορισμένο για complex setups
```


## Ποια να διαλέξεις;

```
Είσαι αρχάριος και μαθαίνεις;
└── pip + venv ✅

Θέλεις γρήγορη εγκατάσταση σε production;
└── pipx ✅

Έχεις παλιά διανομή και δεν νοιάζεσαι για έκδοση;
└── apt/dnf/zypper ✅ (με επιφύλαξη)

Χρειάζεσαι extra Python libraries (boto3, docker κλπ);
└── pip + venv ✅✅
```

> 💡 **Η επιλογή μας:** Συνεχίζουμε με **pip + venv** γιατί:
> - Καταλαβαίνεις **ακριβώς** τι γίνεται
> - Έχεις **πλήρη έλεγχο**
> - Θα χρειαστούμε **extra libraries** για Docker αργότερα
> - Είναι η **ίδια διαδικασία** και στις 3 διανομές
