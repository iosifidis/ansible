# 11.1 Τι είναι το Jinja2 🎨

## Ο ορισμός

Το **Jinja2** είναι ο **template engine** της Ansible — ένας τρόπος να δημιουργείς **δυναμικά αρχεία** από templates με μεταβλητές, loops και conditionals.

> 📝 **Αναλογία:** Σκέψου το Jinja2 σαν **mail merge** στο Word:
> ```
> Template:  "Αγαπητέ {{ name }}, η παραγγελία σας..."
> + Data:    name = "Γιάννη"
> = Output:  "Αγαπητέ Γιάννη, η παραγγελία σας..."
> ```
> Αντί για επιστολές, δημιουργούμε **config αρχεία**!

## Γιατί χρειαζόμαστε Templates;

### Το πρόβλημα χωρίς Templates:

```yaml
# ❌ Χωρίς template — ξεχωριστό αρχείο για κάθε server
tasks:

  # Server 1 — web01
  - name: Copy nginx config for web01
    ansible.builtin.copy:
      src:  files/nginx_web01.conf   # ← ξεχωριστό αρχείο!
      dest: /etc/nginx/nginx.conf

  # Server 2 — web02
  - name: Copy nginx config for web02
    ansible.builtin.copy:
      src:  files/nginx_web02.conf   # ← άλλο ξεχωριστό!
      dest: /etc/nginx/nginx.conf
```

```
# files/nginx_web01.conf
worker_processes 4;        ← hardcoded για web01
server_name web01.example.com;  ← hardcoded

# files/nginx_web02.conf
worker_processes 2;        ← hardcoded για web02
server_name web02.example.com;  ← hardcoded
```

### Η λύση με Templates:

```yaml
# ✅ Με template — ένα αρχείο για ΟΛΟΥΣ τους servers!
tasks:
  - name: Deploy nginx config
    ansible.builtin.template:
      src:  templates/nginx.conf.j2   # ← ένα template
      dest: /etc/nginx/nginx.conf
```

```jinja
{# templates/nginx.conf.j2 #}
worker_processes {{ ansible_facts['processor_vcpus'] }};
{# ↑ αυτόματα από facts! #}

server {
  server_name {{ inventory_hostname }};
  {# ↑ διαφορετικό για κάθε server! #}

  listen {{ http_port | default(80) }};
  root {{ web_root }};
}
```

## Template vs Copy — Πότε το Καθένα

```
┌─────────────────────────────────────────────────────────┐
│  ansible.builtin.copy                                   │
│  ✅ Στατικά αρχεία (ίδια για όλους τους servers)        │
│  ✅ Binary αρχεία                                       │
│  ✅ Αρχεία χωρίς μεταβλητές                             │
│  Παράδειγμα: SSL certificates, images, scripts          │
├─────────────────────────────────────────────────────────┤
│  ansible.builtin.template                               │
│  ✅ Δυναμικά αρχεία (διαφορετικά ανά server)            │
│  ✅ Config αρχεία με μεταβλητές                         │
│  ✅ Αρχεία που εξαρτώνται από facts/vars                │
│  Παράδειγμα: nginx.conf, sshd_config, app.conf          │
└─────────────────────────────────────────────────────────┘
```

## Πού αποθηκεύουμε τα Templates

```
ansible/
├── templates/                    ← κεντρικά templates
│   ├── nginx.conf.j2
│   ├── sshd_config.j2
│   ├── fail2ban_jail.j2
│   └── app.conf.j2
│
└── roles/
    └── nginx/
        └── templates/            ← templates ανά role
            └── nginx.conf.j2
```

> 💡 **Η κατάληξη `.j2`** δεν είναι υποχρεωτική, αλλά είναι **βέλτιστη πρακτική** — δηλώνει ότι είναι Jinja2 template και όχι απλό αρχείο.

## Τι έχει πρόσβαση ένα Template

Μέσα σε ένα template έχεις πρόσβαση σε **όλες** τις μεταβλητές:

```jinja
{# Ansible Facts #}
{{ ansible_facts['hostname'] }}
{{ ansible_facts['os_family'] }}
{{ ansible_facts['processor_vcpus'] }}
{{ ansible_facts['memtotal_mb'] }}
{{ ansible_facts['default_ipv4']['address'] }}

{# Inventory Variables #}
{{ inventory_hostname }}
{{ ansible_host }}
{{ ansible_port }}

{# Play Variables #}
{{ http_port }}
{{ web_root }}
{{ app_name }}

{# group_vars / host_vars #}
{{ service_ssh }}
{{ server_role }}
{{ system_timezone }}

{# Extra Variables (-e flag) #}
{{ app_env }}
```

## Σύνοψη 11.1

```
Jinja2
├── Template engine της Ansible
├── Δημιουργεί δυναμικά αρχεία από templates
├── Πώς λειτουργεί:
│   template + variables → Jinja2 → rendered file → server
├── Γιατί χρειάζεται:
│   ├── Ένα template για όλους τους servers
│   ├── Αυτόματη προσαρμογή βάσει facts/vars
│   └── Αντί για πολλά hardcoded αρχεία
├── Template vs Copy:
│   ├── copy     → στατικά αρχεία
│   └── template → δυναμικά αρχεία με μεταβλητές
├── Αποθήκευση: templates/ directory, .j2 κατάληξη
└── Πρόσβαση σε: facts, inventory vars, play vars,
                  group_vars, host_vars, extra vars
```
