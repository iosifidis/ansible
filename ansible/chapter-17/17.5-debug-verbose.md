# 17.5 Debug Module & Verbose Mode 🔍

## Το debug module

Το `ansible.builtin.debug` είναι το **πιο βασικό εργαλείο** για troubleshooting: εκτυπώνει μηνύματα και τιμές μεταβλητών κατά την εκτέλεση.

```yaml
tasks:

  # ── Εκτύπωση απλού μηνύματος ──────────────
  - name: Μήνυμα
    ansible.builtin.debug:
      msg: "Εκτελούμε σε: {{ inventory_hostname }}"

  # ── Εκτύπωση μεταβλητής ───────────────────
  - name: Τιμή μεταβλητής
    ansible.builtin.debug:
      var: my_variable        # ← χωρίς {{ }}!

  # ── Εκτύπωση register result ──────────────
  - name: Έλεγχος nginx
    ansible.builtin.command:
      cmd: nginx -t
    register:     nginx_check
    changed_when: false
    ignore_errors: true

  - name: Αποτέλεσμα ελέγχου
    ansible.builtin.debug:
      var: nginx_check        # ← ολόκληρο το object
```

## msg vs var — Η διαφορά

```yaml
tasks:

  - name: Ορισμός μεταβλητής
    ansible.builtin.set_fact:
      server_info:
        hostname: nextcloud
        ip:       192.168.1.10
        role:     webserver

  # ── msg: string (υποστηρίζει {{ }}) ──────
  - name: Debug με msg
    ansible.builtin.debug:
      msg: "Server: {{ server_info.hostname }} ({{ server_info.ip }})"
  # Output:
  # ok: [nextcloud] => {
  #     "msg": "Server: nextcloud (192.168.1.10)"
  # }

  # ── var: variable name (χωρίς {{ }}) ─────
  - name: Debug με var
    ansible.builtin.debug:
      var: server_info
  # Output:
  # ok: [nextcloud] => {
  #     "server_info": {
  #         "hostname": "nextcloud",
  #         "ip": "192.168.1.10",
  #         "role": "webserver"
  #     }
  # }
```

## verbosity — Εκτύπωση μόνο σε verbose mode

Το `verbosity` ελέγχει **πότε εμφανίζεται** το debug message:

```yaml
tasks:

  - name: Πάντα εμφανίζεται (default verbosity=0)
    ansible.builtin.debug:
      msg: "Αυτό εμφανίζεται ΠΑΝΤΑ"

  - name: Εμφανίζεται μόνο με -v
    ansible.builtin.debug:
      msg: "Λεπτομέρειες εκτέλεσης..."
      verbosity: 1      # ← -v

  - name: Εμφανίζεται μόνο με -vv
    ansible.builtin.debug:
      msg: "Πολύ αναλυτικά..."
      verbosity: 2      # ← -vv

  - name: Εμφανίζεται μόνο με -vvv
    ansible.builtin.debug:
      var:       full_result    # ← ολόκληρο το object
      verbosity: 3              # ← -vvv
```

```bash
# Εκτέλεση χωρίς verbose → μόνο verbosity: 0
ansible-playbook site.yml --limit nextcloud

# Με -v → verbosity: 0 και 1
ansible-playbook site.yml --limit nextcloud -v

# Με -vv → verbosity: 0, 1, και 2
ansible-playbook site.yml --limit nextcloud -vv
```

> 💡 **Best practice:** Βάλε debugging tasks με `verbosity: 1+` στο playbook σου ώστε να είναι διαθέσιμα αλλά να μην "μολύνουν" το κανονικό output.

## Το assert module — Επαλήθευση συνθηκών

Το `ansible.builtin.assert` **σταματά** το playbook αν μια συνθήκη δεν ισχύει. Ιδανικό για validation.

```yaml
tasks:

  # ── Βασική χρήση ──────────────────────────
  - name: Επαλήθευση OS
    ansible.builtin.assert:
      that:
        - ansible_facts['os_family'] in ['Debian', 'RedHat', 'Suse']
      fail_msg: >
        ❌ Μη υποστηριζόμενο OS:
        {{ ansible_facts['os_family'] }}
      success_msg: >
        ✅ OS υποστηρίζεται:
        {{ ansible_facts['os_family'] }}

  # ── Επαλήθευση πολλαπλών συνθηκών ────────
  - name: System requirements check
    ansible.builtin.assert:
      that:
        - ansible_facts['memtotal_mb'] >= 1024
        - ansible_facts['processor_vcpus'] >= 2
        - ansible_facts['architecture'] == "x86_64"
      fail_msg: |
        ❌ Ανεπαρκής υλικό:
        RAM:  {{ ansible_facts['memtotal_mb'] }}MB (απαιτείται >= 1024)
        CPUs: {{ ansible_facts['processor_vcpus'] }} (απαιτούνται >= 2)
        Arch: {{ ansible_facts['architecture'] }} (απαιτείται x86_64)
      success_msg: "✅ Hardware requirements OK"

  # ── Επαλήθευση μετά από deployment ────────
  - name: Deployment verification
    ansible.builtin.uri:
      url:         "http://localhost:8080/health"
      return_content: true
    register: health_check

  - name: Επαλήθευση health check
    ansible.builtin.assert:
      that:
        - health_check.status == 200
        - "'ok' in health_check.content"
      fail_msg: >
        ❌ Health check απέτυχε!
        Status: {{ health_check.status }}
        Response: {{ health_check.content }}
      success_msg: "✅ Application healthy!"
```

## Verbose Mode — Τα επίπεδα -v

```bash
# ── Χωρίς verbose ─────────────────────────────────────────────
ansible-playbook site.yml --limit nextcloud
# Βλέπεις: task names, ok/changed/failed, play recap

# ── -v (verbosity 1) ──────────────────────────────────────────
ansible-playbook site.yml --limit nextcloud -v
# Βλέπεις: + module output (τι επέστρεψε κάθε module)
# Παράδειγμα:
# ok: [nextcloud] => {"changed": false, "stat": {...}}

# ── -vv (verbosity 2) ─────────────────────────────────────────
ansible-playbook site.yml --limit nextcloud -vv
# Βλέπεις: + input arguments (τι έστειλες στο module)
# Παράδειγμα:
# TASK [Copy config] ***
# ok: [nextcloud] => {"changed": false, ...}
# Args: dest=/etc/nginx/nginx.conf, src=files/nginx.conf

# ── -vvv (verbosity 3) ────────────────────────────────────────
ansible-playbook site.yml --limit nextcloud -vvv
# Βλέπεις: + SSH connections, file transfers
# Παράδειγμα:
# <nextcloud> SSH: EXEC ssh -C -o ControlMaster=auto ...
# <nextcloud> PUT /tmp/ansible-tmp-.../AnsiballZ_apt.py TO ...

# ── -vvvv (verbosity 4) ───────────────────────────────────────
ansible-playbook site.yml --limit nextcloud -vvvv
# Βλέπεις: + SSH debug output (για βαθύ SSH troubleshooting)
# Σπάνια χρησιμοποιείται — πολύ verbose!
```

## Χρήσιμες εντολές troubleshooting

```bash
# ── Dry run — τι ΘΑ έκανε χωρίς να το κάνει ──
ansible-playbook site.yml --limit nextcloud --check

# ── Check + diff — βλέπεις τις αλλαγές ────────
ansible-playbook site.yml --limit nextcloud --check --diff

# ── Syntax check ──────────────────────────────
ansible-playbook site.yml --syntax-check

# ── Λίστα tasks που θα εκτελεστούν ────────────
ansible-playbook site.yml --list-tasks

# ── Λίστα hosts που θα επηρεαστούν ───────────
ansible-playbook site.yml --list-hosts

# ── Εκτέλεση από συγκεκριμένο task ───────────
ansible-playbook site.yml \
    --limit nextcloud \
    --start-at-task "Εγκατάσταση nginx"

# ── Step-by-step εκτέλεση ─────────────────────
ansible-playbook site.yml --limit nextcloud --step
# Ρωτά πριν κάθε task: Perform this task? (y/n/c)

# ── Έλεγχος inventory ─────────────────────────
ansible-inventory --list
ansible-inventory --graph

# ── Test σύνδεσης ─────────────────────────────
ansible all -m ping -v
ansible nextcloud -m setup | grep -i memory
```

## Pattern: Pre-flight checks

Ένα κλασικό pattern είναι να κάνεις **ελέγχους πριν ξεκινήσει το playbook**:

```yaml
---
# site.yml με pre-flight checks

- name: Pre-flight Checks
  hosts: all
  gather_facts: true

  tasks:

    - name: "🔍 Έλεγχος OS"
      ansible.builtin.assert:
        that:
          - ansible_facts['os_family'] in ['Debian', 'RedHat', 'Suse']
        fail_msg: "❌ Μη υποστηριζόμενο OS: {{ ansible_facts['os_family'] }}"

    - name: "🔍 Έλεγχος RAM"
      ansible.builtin.assert:
        that:
          - ansible_facts['memtotal_mb'] >= 512
        fail_msg: >
          ❌ Ανεπαρκής RAM:
          {{ ansible_facts['memtotal_mb'] }}MB < 512MB

    - name: "🔍 Έλεγχος disk"
      ansible.builtin.shell:
        cmd: "df / | tail -1 | awk '{print $5}' | tr -d '%'"
      register:     disk_pct
      changed_when: false

    - name: "🔍 Επαλήθευση ελεύθερου disk"
      ansible.builtin.assert:
        that:
          - disk_pct.stdout | int < 85
        fail_msg: >
          ❌ Disk σχεδόν γεμάτος:
          {{ disk_pct.stdout }}% used (όριο: 85%)

    - name: "🔍 Έλεγχος Python"
      ansible.builtin.command:
        cmd: python3 --version
      register:     python_ver
      changed_when: false

    - name: "✅ Pre-flight checks ολοκληρώθηκαν"
      ansible.builtin.debug:
        msg:
          - "OS   : {{ ansible_facts['distribution'] }} {{ ansible_facts['distribution_version'] }}"
          - "RAM  : {{ ansible_facts['memtotal_mb'] }}MB"
          - "Disk : {{ disk_pct.stdout }}% used"
          - "Python: {{ python_ver.stdout }}"

- name: Main Playbook
  hosts: all
  become: true
  # ... rest of the playbook
```

## Σύνοψη 17.5

```
Debug Module & Verbose Mode
│
├── debug module:
│   ├── msg: "..."    → εκτύπωση μηνύματος (με {{ }})
│   ├── var: name     → εκτύπωση μεταβλητής (χωρίς {{ }})
│   └── verbosity: N  → εμφανίζεται μόνο με -v*N
│
├── assert module:
│   ├── that: [conditions]   → συνθήκες προς έλεγχο
│   ├── fail_msg: "..."      → μήνυμα αν αποτύχει
│   └── success_msg: "..."   → μήνυμα αν επιτύχει
│
├── Verbose levels:
│   ├── (κανένα) → task names + play recap
│   ├── -v       → + module output
│   ├── -vv      → + input arguments
│   ├── -vvv     → + SSH connections
│   └── -vvvv    → + SSH debug
│
└── Χρήσιμες flags:
    ├── --check      → dry run
    ├── --diff       → εμφάνιση αλλαγών
    ├── --step       → βήμα-βήμα
    ├── --start-at-task → από συγκεκριμένο task
    └── --syntax-check → έλεγχος σύνταξης
```
