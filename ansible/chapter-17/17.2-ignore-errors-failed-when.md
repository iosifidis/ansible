# 17.2 ignore_errors & failed_when ❌

## ignore_errors — «Αγνόησε και συνέχισε»

Το `ignore_errors: true` λέει στην Ansible: **«Ακόμα κι αν αποτύχει αυτό το task, συνέχισε με το επόμενο»**.

```yaml
tasks:

  - name: Σταμάτα το service (αν τρέχει)
    ansible.builtin.service:
      name:  myapp
      state: stopped
    ignore_errors: true     # ← αν δεν υπάρχει → συνέχισε

  - name: Αυτό εκτελείται ΠΑΝΤΑ
    ansible.builtin.debug:
      msg: "Έφτασα εδώ ανεξάρτητα από το προηγούμενο!"
```

> ⚠️ **Σημαντικό:** Το `ignore_errors` δεν «κρύβει» το σφάλμα — εμφανίζεται στο output ως `...ignoring`. Απλά δεν σταματά το playbook.

---

## Πότε να χρησιμοποιείς ignore_errors

```yaml
tasks:

  # ✅ Σωστή χρήση: task που μπορεί να αποτύχει φυσιολογικά
  - name: Αφαίρεση παλιού config (μπορεί να μην υπάρχει)
    ansible.builtin.file:
      path:  /etc/myapp/old.conf
      state: absent
    ignore_errors: true

  # ✅ Σωστή χρήση: έλεγχος που μπορεί να επιστρέψει error
  - name: Έλεγχος αν PostgreSQL τρέχει
    ansible.builtin.command:
      cmd: pg_isready
    register:      pg_status
    ignore_errors: true

  - name: Εκκίνηση PostgreSQL αν δεν τρέχει
    ansible.builtin.service:
      name:  postgresql
      state: started
    when: pg_status.rc != 0

  # ❌ Λάθος χρήση: κρύβεις πραγματικά σφάλματα
  - name: Εγκατάσταση nginx
    ansible.builtin.apt:
      name: nginx
    ignore_errors: true   # ← αν αποτύχει, δεν θα ξέρεις!
```

## Καταγραφή με register + ignore_errors

Συνδυάζοντας `register` και `ignore_errors`, μπορείς να **καταγράψεις το αποτέλεσμα** και να αποφασίσεις αργότερα:

```yaml
tasks:

  # ── Εκτέλεση ──────────────────────────────
  - name: Δοκιμή σύνδεσης στη βάση
    ansible.builtin.command:
      cmd: "mysql -u root -e 'SELECT 1'"
    register:      db_check
    ignore_errors: true
    changed_when:  false        # ← δεν αλλάζει τίποτα

  # ── Αναφορά αποτελέσματος ──────────────────
  - name: Εμφάνιση κατάστασης βάσης
    ansible.builtin.debug:
      msg: >
        MySQL:
        {{ '✅ OK' if db_check.rc == 0
                  else '❌ ΑΠΟΤΥΧΙΑ: ' + db_check.stderr }}

  # ── Ενέργεια ανάλογα με αποτέλεσμα ──────────
  - name: Εκκίνηση MySQL αν δεν τρέχει
    ansible.builtin.service:
      name:  mysql
      state: started
    when: db_check.rc != 0
```

## failed_when — Custom Κριτήριο Αποτυχίας

Το `failed_when` σου επιτρέπει να **ορίσεις εσύ** πότε ένα task θεωρείται αποτυχημένο — ανεξάρτητα από το exit code.

> 📝 **Αναλογία:**
> ```
> Κανονική συμπεριφορά:
>   exit code 0 → επιτυχία
>   exit code 1 → αποτυχία
>
> failed_when:
>   exit code 0, αλλά output = "ERROR" → αποτυχία ❌
>   exit code 1, αλλά αναμενόμενο → επιτυχία ✅
> ```

---

## failed_when — Παραδείγματα

### Αποτυχία βάσει output

```yaml
tasks:

  - name: Έλεγχος κατάστασης εφαρμογής
    ansible.builtin.command:
      cmd: /opt/myapp/bin/health-check
    register:    app_health
    failed_when: "'ERROR' in app_health.stdout"
    #             ↑ αποτύχει αν το output περιέχει "ERROR"
    #               ακόμα κι αν exit code = 0!
    changed_when: false
```

### Αποτυχία βάσει return code

```yaml
tasks:

  - name: Αναζήτηση στο log
    ansible.builtin.command:
      cmd: "grep -c 'CRITICAL' /var/log/myapp.log"
    register:    critical_count
    # exit code 1 = grep δεν βρήκε = OK για εμάς
    # exit code >1 = grep error = πραγματικό πρόβλημα
    failed_when: critical_count.rc > 1
    changed_when: false
```

### Αποτυχία βάσει πολλαπλών συνθηκών

```yaml
tasks:

  - name: Deployment check
    ansible.builtin.uri:
      url:            http://localhost:8080/health
      return_content: true
    register:    health_response
    failed_when:
      - health_response.status != 200
      - "'ok' not in health_response.content"
    # ↑ Αποτυγχάνει ΜΟΝΟ αν ισχύουν ΚΑΙ ΟΙ ΔΥΟ
```

### Συνδυασμός failed_when + ignore_errors

```yaml
tasks:

  - name: Παρατεταμένος έλεγχος (με timeout)
    ansible.builtin.command:
      cmd:  "timeout 30 /opt/check.sh"
    register:      check_result
    failed_when:
      - check_result.rc != 0
      - check_result.rc != 124   # ← 124 = timeout (αποδεκτό)
    ignore_errors: true
    changed_when:  false
```

## Σύγκριση ignore_errors vs failed_when

```
┌─────────────────────────────────────────────────────────┐
│  ignore_errors: true          │  failed_when: condition  │
├─────────────────────────────────────────────────────────┤
│  Αγνοεί ΠΑΝΤΑ το σφάλμα       │  Ορίζει ΠΟΤΕ είναι       │
│                               │  σφάλμα                  │
├─────────────────────────────────────────────────────────┤
│  Απλούστερο                   │  Πιο ακριβές              │
├─────────────────────────────────────────────────────────┤
│  Πάντα «συνεχίζει»            │  Σταματά αν ισχύει η      │
│                               │  συνθήκη                 │
├─────────────────────────────────────────────────────────┤
│  Χρήση: task που ΠΑΝΤΑ        │  Χρήση: command με        │
│  μπορεί να αποτύχει           │  ιδιαίτερη λογική         │
│  (π.χ. αφαίρεση αρχείου)      │  exit codes/output        │
└─────────────────────────────────────────────────────────┘
```

## Πρακτικό παράδειγμα — Service Management

```yaml
---
# service-error-handling.yml

- name: Service Management με Error Handling
  hosts: all
  become: true
  gather_facts: true

  vars:
    services:
      - { name: nginx,      critical: true  }
      - { name: redis,      critical: true  }
      - { name: myapp,      critical: true  }
      - { name: monitoring, critical: false }

  tasks:

    # ── Έλεγχος κατάστασης services ──────────
    - name: Έλεγχος service {{ item.name }}
      ansible.builtin.command:
        cmd: "systemctl is-active {{ item.name }}"
      register:      svc_status
      ignore_errors: true
      changed_when:  false
      loop: "{{ services }}"
      loop_control:
        label: "{{ item.name }}"

    # ── Αναφορά ───────────────────────────────
    - name: Κατάσταση services
      ansible.builtin.debug:
        msg: >
          {{ item.item.name }}:
          {{ '✅ active' if item.rc == 0
                        else '❌ inactive' }}
          {{ '[ΚΡΙΣΙΜΟ]' if item.item.critical else '' }}
      loop: "{{ svc_status.results }}"
      loop_control:
        label: "{{ item.item.name }}"

    # ── Εκκίνηση critical services ────────────
    - name: Εκκίνηση critical service {{ item.item.name }}
      ansible.builtin.service:
        name:  "{{ item.item.name }}"
        state: started
      when:
        - item.rc != 0
        - item.item.critical
      loop: "{{ svc_status.results }}"
      loop_control:
        label: "{{ item.item.name }}"

    # ── Επαλήθευση ────────────────────────────
    - name: Τελικός έλεγχος κρίσιμων services
      ansible.builtin.command:
        cmd: "systemctl is-active {{ item.name }}"
      register:     final_check
      failed_when:  final_check.rc != 0
      #             ↑ ΕΔΩ αποτυγχάνουμε αν critical service
      #               ακόμα δεν τρέχει!
      changed_when: false
      loop: "{{ services | selectattr('critical') | list }}"
      loop_control:
        label: "{{ item.name }}"
```

```bash
# Εκτέλεση
ansible-playbook playbooks/service-error-handling.yml \
    --limit nextcloud -v
```

## Σύνοψη 17.2

```
ignore_errors & failed_when
│
├── ignore_errors: true
│   ├── Αγνοεί το σφάλμα → συνεχίζει
│   ├── Το σφάλμα εμφανίζεται ως "...ignoring"
│   └── Συνδύασε πάντα με register για έλεγχο
│
└── failed_when: <condition>
    ├── Ορίζεις ΕΣΥ πότε είναι αποτυχία
    ├── Μπορεί να βασίζεται σε:
    │   ├── .rc  (return code)
    │   ├── .stdout / .stderr (output)
    │   └── Συνδυασμός συνθηκών
    └── Αντίθετο: failed_when: false
        → ΠΟΤΕ δεν θεωρείται αποτυχία
```
