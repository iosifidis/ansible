# 2.2 Users — Ποιος χρησιμοποιεί την Ansible 👤

## Τι εννοούμε με τον όρο "User"

Στην Ansible, ο όρος **"User"** αναφέρεται σε **δύο διαφορετικά επίπεδα**:

1. **Εσύ** — αυτός που γράφει και εκτελεί τα playbooks (από το Armbian controller)
2. **Ο χρήστης με τον οποίο η Ansible συνδέεται** στους remote servers

Ας τα δούμε και τα δύο αναλυτικά.

---

## Επίπεδο 1: Ο χρήστης που εκτελεί την Ansible

Αυτός είναι **εσύ** — ο sysadmin/DevOps που κάθεται μπροστά στο terminal.

```bash
# Εσύ συνδέεσαι στο Armbian controller
ssh stathis@armbian-server

# Και από εκεί εκτελείς την Ansible
ansible-playbook my_playbook.yml
```

> 📝 **Σημείωση:** Ο χρήστης που εκτελεί την Ansible στον controller **δεν χρειάζεται να είναι root**. Στην πραγματικότητα, είναι **βέλτιστη πρακτική να μην είναι root**.

---

## Επίπεδο 2: Ο χρήστης με τον oποίο η Ansible συνδέεται στους Servers

Όταν η Ansible τρέχει ένα playbook, **συνδέεται μέσω SSH** στους managed servers. Χρησιμοποιεί έναν συγκεκριμένο χρήστη για αυτή τη σύνδεση.

```
Armbian Controller
       │
       │  SSH ως χρήστης "ansible"
       │
       ▼
  [Managed Server]
  - Συνδέεται ως: ansible
  - Εκτελεί tasks ως: root (μέσω sudo)
```

---

## Η βέλτιστη πρακτική: Dedicated "ansible" User

Στον πραγματικό κόσμο, δημιουργούμε έναν **ξεχωριστό χρήστη** αποκλειστικά για την Ansible σε κάθε managed server:

```yaml
# Παράδειγμα: Δημιουργία dedicated ansible user
- name: Create ansible user on managed servers
  hosts: all
  tasks:

    - name: Create ansible user
      ansible.builtin.user:
        name: ansible          # το όνομα του χρήστη
        shell: /bin/bash       # το shell του
        create_home: true      # δημιουργία home directory
        state: present

    - name: Add ansible user to sudoers
      ansible.builtin.lineinfile:
        path: /etc/sudoers.d/ansible
        line: 'ansible ALL=(ALL) NOPASSWD: ALL'
        create: true
        mode: '0440'           # σωστά permissions για sudoers
        validate: 'visudo -cf %s'  # επαλήθευση πριν αποθηκευτεί
```

> ⚠️ **Ασφάλεια:** Το `NOPASSWD: ALL` σημαίνει ότι ο ansible user μπορεί να τρέξει sudo **χωρίς password**. Αυτό είναι αποδεκτό **μόνο** γιατί:
> - Η πρόσβαση γίνεται **μόνο με SSH key** (όχι password)
> - Ο χρήστης χρησιμοποιείται **αποκλειστικά** από την Ansible

---

## Πώς ορίζουμε τον χρήστη στην Ansible

Έχουμε **τρεις τρόπους** να πούμε στην Ansible με ποιον χρήστη να συνδεθεί:

### Τρόπος 1: Στο Playbook (για συγκεκριμένο playbook)
```yaml
- name: My playbook
  hosts: all
  remote_user: ansible        # ← ο χρήστης σύνδεσης
  become: true                # ← χρησιμοποίησε sudo
  become_user: root           # ← γίνε root μέσω sudo
  tasks:
    - name: Install nginx
      ansible.builtin.package:
        name: nginx
        state: present
```

### Τρόπος 2: Στο Inventory (για συγκεκριμένους servers)
```ini
# hosts.ini
[webservers]
server1 ansible_user=ansible ansible_become=true
server2 ansible_user=deploy  ansible_become=true
```

### Τρόπος 3: Στο ansible.cfg (global — για όλα)
```ini
# ansible.cfg
[defaults]
remote_user = ansible

[privilege_escalation]
become = true
become_method = sudo
become_user = root
```

> 💡 **Συμβουλή:** Στην πράξη χρησιμοποιούμε **συνδυασμό**: global ρυθμίσεις στο `ansible.cfg` και override όπου χρειάζεται στο playbook ή inventory.

## Σύνοψη του 2.2

```
User στην Ansible
├── Εσύ (controller user)
│   └── Εκτελείς ansible-playbook από το Armbian
│
└── Remote user (σε κάθε managed server)
    ├── Συνδέεται μέσω SSH key (όχι password!)
    ├── Είναι dedicated "ansible" user
    └── Έχει sudo δικαιώματα χωρίς password
```
