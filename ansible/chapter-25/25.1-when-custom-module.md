# 25.1 Πότε χρειάζεσαι Custom Module 🤔

## Module vs Role vs Task

```
Επίλεξε το σωστό εργαλείο:

Task (existing modules):
  → Η Ansible ήδη το κάνει
  → ansible.builtin.*, community.*
  → Χρησιμοποίησε αυτό ΠΑΝΤΑ πρώτα!

Role:
  → Οργάνωση πολλών tasks
  → Reusable configuration
  → Δεν χρειάζεται Python

Custom Module:
  → Η Ansible ΔΕΝ έχει module για αυτό
  → Πολύπλοκη λογική σε Python
  → Idempotent behavior
  → Εξωτερικό API / proprietary system
```

---

## Παραδείγματα καλής χρήσης custom module

```python
# Καλά σενάρια:
# ✅ API call σε proprietary system (π.χ. εσωτερικό CMDB)
# ✅ Complex idempotent checks που δεν μπορούν με shell
# ✅ Επικοινωνία με database query
# ✅ Custom hardware/firmware management

# Κακά σενάρια (αντί για module, χρησιμοποίησε άλλο):
# ❌ Χρησιμοποίησε uri module αντί για HTTP requests
# ❌ Χρησιμοποίησε command/shell για simple scripts
# ❌ Χρησιμοποίησε template αντί για file generation
```

---

## Πού βάζεις τα modules

```
project/
├── library/              ← Custom modules (αυτόματα load!)
│   └── my_module.py
├── filter_plugins/       ← Custom Jinja2 filters
│   └── my_filters.py
├── callback_plugins/     ← Custom output
│   └── my_callback.py
└── playbooks/
    └── site.yml
```

---

## Σύνοψη 25.1

```
Custom Module — Πότε:
├── Proprietary APIs / systems
├── Complex idempotent logic
└── ΌΧΙ αν υπάρχει ήδη module!
```
