# 23.1 Γιατί Git για Ansible; 📚

## Infrastructure as Code (IaC)

Τα Ansible playbooks, roles και configs είναι **κώδικας** — και ο κώδικας πρέπει να είναι στο Git.

```
Χωρίς Git:
  ├── "Ποιος άλλαξε το nginx role;"  → αδύνατο να ξέρεις
  ├── "Πότε σπάσε το production;"    → αδύνατο να βρεις
  ├── "Ποια ήταν η προηγούμενη έκδοση;" → χαμένη
  └── "Τι αλλαγές έγιναν χθες;"     → κανείς δεν θυμάται

Με Git:
  ├── git log --oneline roles/nginx/ → ιστορικό αλλαγών
  ├── git blame playbooks/deploy.yml → ποιος άλλαξε τι
  ├── git diff HEAD~1                → τι άλλαξε χθες
  └── git revert abc123             → rollback σε 30 δευτερόλεπτα!
```

---

## Single Source of Truth

```
Git Repository = ο μόνος αληθινός ορισμός της υποδομής:
│
├── Τι εκτελείται σε production; → git show main:playbooks/deploy.yml
├── Τι διαφέρει testing από production? → git diff develop main
├── Πότε κάναμε deploy; → git log --oneline main
└── Ποιος έκανε approve; → git log --show-signature
```

---

## Τι μπαίνει στο Git

```
✅ ΝΑΙ — στο Git:
├── Playbooks (*.yml)
├── Roles (roles/*/tasks, handlers, templates, defaults)
├── Inventory (hosts.ini, hosts.yml)
├── Group/host vars (εκτός secrets!)
├── ansible.cfg
├── requirements.yml
├── molecule tests
├── .ansible-lint
└── .github/workflows/

⛔ ΟΧΙ — ΔΕΝ μπαίνει στο Git:
├── vault secrets (αν δεν είναι encrypted!)
├── ~/.ssh/private_keys
├── .vault_pass
├── .env με passwords
└── deploy_key (private part)

# .gitignore για Ansible project:
*.vault_pass
.vault_password
.env
*.pem
*.key
!*.pub
.molecule/
__pycache__/
*.pyc
```

## Σύνοψη 23.1

```
Git για Ansible:
│
├── Ιστορικό: ποιος/τι/πότε άλλαξε
├── Rollback: git revert → άμεσο undo
├── Συνεργασία: review πριν deploy
├── Audit: πλήρες audit trail
└── ΔΕΝ μπαίνει: private keys, vault passwords
```
