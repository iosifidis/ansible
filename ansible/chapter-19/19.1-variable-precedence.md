# 19.1 Τα 22 Επίπεδα Προτεραιότητας 📊

## Το πρόβλημα

Η Ansible επιτρέπει να ορίσεις μεταβλητές σε **πολλά μέρη** — playbook, inventory, group_vars, command line, κ.ά. Αν δύο μέρη ορίζουν την **ίδια μεταβλητή**, ποιο κερδίζει;

> 📝 **Αναλογία:** Σκέψου τη σειρά προτεραιότητας σαν **νόμο της χώρας**:
> ```
> Σύνταγμα (ανώτατο)          → extra_vars (-e)
> Νόμοι                       → role vars
> Κανονισμοί                  → playbook vars
> Τοπικές αποφάσεις           → group_vars
> Προεπιλογές συστήματος      → role defaults
> ```

---

## Τα 22 επίπεδα (από χαμηλότερο → υψηλότερο)

```
  Χαμηλότερη προτεραιότητα (εύκολα override)
  ═══════════════════════════════════════════

  1.  role defaults          ← defaults/main.yml
  2.  inventory file vars    ← hosts.ini μεταβλητές
  3.  inventory group_vars   ← group_vars/ (από inventory dir)
  4.  inventory host_vars    ← host_vars/ (από inventory dir)
  5.  playbook group_vars/all
  6.  playbook group_vars/*  ← κάθε group
  7.  playbook host_vars/*   ← κάθε host
  8.  host facts             ← gather_facts
  9.  play vars              ← vars: στο play
  10. play vars_prompt       ← ερώτηση χρήστη
  11. play vars_files        ← vars_files: στο play
  12. role vars              ← vars/main.yml
  13. block vars             ← vars: σε block
  14. task vars              ← vars: σε task
  15. include_vars           ← ansible.builtin.include_vars
  16. set_facts / registered vars
  17. role (and include_role) params
  18. include params
  19. extra vars (-e)        ← ΠΑΝΤΑ κερδίζει!

  ═══════════════════════════════════════════
  Υψηλότερη προτεραιότητα (δύσκολα override)
```

> 💡 **Απλοποιημένος κανόνας που θυμάσαι:**
> ```
> role defaults < group_vars < host_vars < play vars
> < role vars < task vars < set_fact < extra_vars (-e)
> ```

## Παράδειγμα conflict — Ποιο κερδίζει;

```
Σενάριο: μεταβλητή "nginx_port" ορίζεται παντού

role defaults/main.yml:
  nginx_port: 80              ← επίπεδο 1 (χαμηλότερο)

group_vars/webservers.yml:
  nginx_port: 8080            ← επίπεδο 6

host_vars/nextcloud.yml:
  nginx_port: 8443            ← επίπεδο 7

playbook vars:
  nginx_port: 9000            ← επίπεδο 9

ansible-playbook ... -e "nginx_port=443"
                              ← επίπεδο 19 (υψηλότερο)

Αποτέλεσμα: nginx_port = 443  ← extra_vars κερδίζει ΠΑΝΤΑ
```

---

## Επίπεδο 1: role defaults — Η «βάση»

```yaml
# roles/nginx/defaults/main.yml
nginx_port:       80
nginx_worker_processes: auto
nginx_keepalive_timeout: 65
nginx_max_body_size: "1m"
```

> 💡 **Φιλοσοφία:** Τα `defaults` είναι οι **λογικές προεπιλογές** — κάτι που δουλεύει χωρίς καμία ρύθμιση, αλλά μπορεί εύκολα να αλλαχτεί από όλα τα άλλα επίπεδα.

---

## Επίπεδο 12: role vars — «Κλειδωμένες» τιμές

```yaml
# roles/nginx/vars/main.yml
# Αυτές ΔΥΣΚΟΛΑ αλλάζουν — override μόνο από extra_vars
nginx_config_dir:  /etc/nginx
nginx_log_dir:     /var/log/nginx
nginx_pid_file:    /run/nginx.pid
```

> ⚠️ **Διαφορά defaults vs vars:**
> ```
> defaults/main.yml → εύκολο override (group_vars, host_vars...)
> vars/main.yml     → δύσκολο override (μόνο task vars, set_fact, -e)
> ```

## Οπτικοποίηση: Πού να βάλεις τι

```
Ερώτηση: Πού βάζω τη μεταβλητή;
│
├── Είναι default τιμή που μπορεί να αλλαχτεί;
│   └── role defaults/main.yml  ← επίπεδο 1
│
├── Αφορά συγκεκριμένο environment (prod/staging)?
│   └── group_vars/production.yml  ← επίπεδο 6
│
├── Αφορά συγκεκριμένο host?
│   └── host_vars/nextcloud.yml  ← επίπεδο 7
│
├── Πρέπει να είναι ΠΑΝΤΑ αυτή η τιμή;
│   └── role vars/main.yml  ← επίπεδο 12
│
└── Θέλω override για αυτή μόνο την εκτέλεση;
    └── ansible-playbook -e "var=value"  ← επίπεδο 19
```

## Debugging: Ποια τιμή χρησιμοποιείται;

```bash
# Δες ποια τιμή θα χρησιμοποιηθεί για ένα host
ansible nextcloud -m ansible.builtin.debug \
    -a "var=nginx_port"

# Με verbose — δες από πού προέρχεται
ansible-playbook site.yml \
    --limit nextcloud \
    --list-tasks -v

# Όλες οι μεταβλητές ενός host
ansible nextcloud -m ansible.builtin.setup | grep -A2 nginx
```

```yaml
# Μέσα στο playbook — debugging precedence
tasks:
  - name: Debug nginx_port source
    ansible.builtin.debug:
      msg:
        - "nginx_port = {{ nginx_port }}"
        - "Τύπος: {{ nginx_port | type_debug }}"
```

```
