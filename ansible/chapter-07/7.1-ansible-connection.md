# 7.1 Πώς συνδέεται η Ansible — SSH Deep Dive 🔍

## Η βασική αρχή

Η Ansible χρησιμοποιεί **SSH** για να επικοινωνεί με τους remote servers. Δεν χρειάζεται κανένας agent — μόνο SSH.

```
┌─────────────────────────────────────────────────────────┐
│  Armbian Controller                                     │
│  (ansible user)                                         │
│       │                                                 │
│       │  1. Ανοίγει SSH σύνδεση                         │
│       │  2. Μεταφέρει Python script                     │
│       │  3. Εκτελεί το script                           │
│       │  4. Παίρνει αποτέλεσμα (JSON)                   │
│       │  5. Κλείνει SSH σύνδεση                         │
│       │                                                 │
│       ▼                                                 │
│  [Managed Server]                                       │
│  nextcloud                                              │
└─────────────────────────────────────────────────────────┘
```

---

## Η ροή σύνδεσης — Βήμα προς βήμα

Όταν εκτελείς ένα playbook, η Ansible κάνει αυτά **για κάθε task**:

```
┌─────────────────────────────────────────────────────────┐
│  ΒΗΜΑ 1: Έλεγχος Inventory                              │
│  → Βρίσκει τον host (IP, port, user, key)               │
├─────────────────────────────────────────────────────────┤
│  ΒΗΜΑ 2: Gathering Facts (αν είναι ενεργό)              │
│  → Ανοίγει SSH                                          │
│  → Τρέχει setup module                                  │
│  → Μαζεύει πληροφορίες συστήματος                       │
│  → Κλείνει SSH (ή κρατά ανοιχτό με ControlMaster)       │
├─────────────────────────────────────────────────────────┤
│  ΒΗΜΑ 3: Για κάθε Task                                  │
│  → Ετοιμάζει Python script (το module)                  │
│  → Ανοίγει SSH (ή reuse με ControlMaster)               │
│  → Αντιγράφει script στον /tmp/ του server              │
│  → Εκτελεί: python3 /tmp/ansible_script.py              │
│  → Παίρνει JSON αποτέλεσμα                              │
│  → Διαγράφει το script από /tmp/                        │
│  → Κλείνει SSH                                          │
├─────────────────────────────────────────────────────────┤
│  ΒΗΜΑ 4: Handlers (αν υπάρχουν)                         │
│  → Εκτελούνται στο τέλος                                │
└─────────────────────────────────────────────────────────┘
```

## Τι γίνεται "Κάτω από το καπό"

Ας το δούμε με **verbose mode**:

```bash
# -vvvv = maximum verbosity
ansible nextcloud -m ansible.builtin.ping -vvvv
```

```
# Τι θα δεις:
ESTABLISH SSH CONNECTION FOR USER: ansible          ← σύνδεση
SSH: EXEC ssh -C -o ControlMaster=auto \
     -o ControlPersist=60s \
     -o StrictHostKeyChecking=no \
     -i /home/ansible/.ssh/id_ed25519 \
     -p 2022 \
     83.212.104.27 \                                ← παράμετροι
     '/bin/sh -c '"'"'...'

EXEC /bin/sh -c 'LANG=... python3 /tmp/ping.py'   ← εκτέλεση
RESULT: {"ping": "pong", "changed": false}          ← αποτέλεσμα
```

## Το SSH Command που χρησιμοποιεί η Ansible

Η Ansible **κατασκευάζει** αυτόματα την SSH εντολή:

```bash
# Αυτό βλέπεις με -vvvv
ssh \
  -C \                              # compression
  -o ControlMaster=auto \           # connection reuse
  -o ControlPersist=60s \           # κράτα σύνδεση 60s
  -o StrictHostKeyChecking=no \     # host_key_checking=False
  -i /home/ansible/.ssh/id_ed25519\ # private key
  -p 2022 \                         # custom port
  ansible@83.212.104.27 \           # user@host
  '/bin/sh -c "python3 /tmp/..."'   # εντολή
```

> 📝 **Σημείωση:** Αυτές οι παράμετροι προέρχονται από το `ansible.cfg` μας:
```ini
[ssh_connection]
pipelining = True
ssh_args   = -C -o ControlMaster=auto -o ControlPersist=60s
```

## Pipelining — Πώς επιταχύνει τη σύνδεση

```
ΧΩΡΙΣ pipelining:
─────────────────
Task 1:
  [SSH open] → copy script → execute → [SSH close]
Task 2:
  [SSH open] → copy script → execute → [SSH close]
Task 3:
  [SSH open] → copy script → execute → [SSH close]

Σύνολο: 3 SSH connections × overhead = αργό ❌

═══════════════════════════════════════════════════

ΜΕ pipelining:
──────────────
[SSH open]
  Task 1: stdin → execute → stdout
  Task 2: stdin → execute → stdout
  Task 3: stdin → execute → stdout
[SSH close]

Σύνολο: 1 SSH connection = γρήγορο ✅
```

---

## ControlMaster — Reuse Connections

```
ΧΩΡΙΣ ControlMaster:
────────────────────
Play με 10 tasks:
→ 10 × [TCP handshake + SSH auth + encrypt] = αργό ❌

ΜΕ ControlMaster:
─────────────────
1η σύνδεση: [TCP handshake + SSH auth + encrypt]
Tasks 2-10: reuse existing socket ✅

Socket αποθηκεύεται:
~/.ansible/cp/hostname-port-user
```

```bash
# Δες τα active ControlMaster sockets
ls ~/.ansible/cp/
# ansible@83.212.104.27:2022   ← ενεργή σύνδεση!

# Κλείσε όλα τα sockets
ssh -O stop -o ControlPath=~/.ansible/cp/\* dummy
```

## Gather Facts — Τι μαζεύει η Ansible

```bash
# Δες ΟΛΑ τα facts που μαζεύει
ansible nextcloud -m ansible.builtin.setup | less

# Τα πιο σημαντικά:
ansible nextcloud -m ansible.builtin.setup \
    -a "filter=ansible_distribution*,ansible_os_family,\
ansible_kernel,ansible_architecture,ansible_memtotal_mb,\
ansible_processor_vcpus,ansible_default_ipv4"
```

```yaml
# Αναμενόμενο output (τα σημαντικότερα):
ansible_facts:
  ansible_architecture:        x86_64
  ansible_distribution:        Debian
  ansible_distribution_release: bookworm
  ansible_distribution_version: "12.13"
  ansible_kernel:              6.1.0-41-amd64
  ansible_memtotal_mb:         1976
  ansible_os_family:           Debian
  ansible_processor_vcpus:     4
  ansible_default_ipv4:
    address: 83.212.104.27
    interface: eth1
    gateway: 83.212.104.1
```

## Σύνδεση χωρίς Gather Facts

```yaml
# Απενεργοποίηση για ταχύτερη εκτέλεση
- name: Quick play
  hosts: all
  gather_facts: false    # ← παρακάμπτει το setup module

  tasks:
    - name: Γρήγορη εντολή
      ansible.builtin.command: uptime
```

```bash
# Σύγκριση χρόνου
time ansible-playbook playbooks/test.yml                  # με facts
time ansible-playbook playbooks/test.yml --skip-tags setup # χωρίς facts

# Διαφορά: ~2-3 δευτερόλεπτα ανά server!
# Σε 50 servers = 100-150 δευτερόλεπτα εξοικονόμηση
```

> ⚠️ **Πότε να απενεργοποιήσεις τα Facts:**
```
✅ Απλές εντολές που δεν χρειάζονται πληροφορίες συστήματος
✅ Playbooks που τρέχουν πολύ συχνά
❌ Playbooks που χρησιμοποιούν ansible_os_family, ansible_distribution κλπ
```

## Η Σύνδεση σε αριθμούς

```
Τι συμβαίνει όταν τρέχεις:
ansible-playbook playbooks/security-bootstrap.yml --limit nextcloud

1. Ansible διαβάζει ansible.cfg          → ~0.1s
2. Ansible διαβάζει inventory            → ~0.1s
3. SSH connect + auth                    → ~0.5s
4. Gathering Facts (setup module)        → ~1-2s
5. Κάθε task (με pipelining)             → ~0.2-0.5s
6. Handlers                              → ~0.5s

Σύνολο για 15 tasks: ~8-12 δευτερόλεπτα
```

## Σύνοψη 7.1

```
SSH Deep Dive
├── Ansible χρησιμοποιεί SSH (agentless)
├── Για κάθε task:
│   ├── Ανοίγει SSH (ή reuse)
│   ├── Αντιγράφει Python script
│   ├── Εκτελεί & παίρνει JSON
│   └── Κλείνει SSH
├── Pipelining → 1 SSH connection για όλα τα tasks
├── ControlMaster → reuse existing connections
├── Gather Facts → συλλογή πληροφοριών συστήματος
└── Verbose (-vvvv) → βλέπεις τα πάντα
```
