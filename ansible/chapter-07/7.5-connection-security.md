# 7.5 Ασφάλεια σύνδεσης 🔐

## Γιατί είναι κρίσιμη η ασφάλεια;

Ο Manager Server έχει **SSH πρόσβαση** σε όλους τους managed servers. Αν παραβιαστεί, **όλοι** οι servers είναι εκτεθειμένοι. Γι' αυτό η ασφάλεια της σύνδεσης είναι **κρίσιμη**.

```
┌─────────────────────────────────────────────────────────┐
│  Αν παραβιαστεί ο Manager Server:                       │
│                                                         │
│  Armbian Controller (παραβιασμένος!) ❌                 │
│       │                                                 │
│       ├──────────► nextcloud    (εκτεθειμένο!) ❌       │
│       ├──────────► rocky01      (εκτεθειμένο!) ❌       │
│       └──────────► suse01       (εκτεθειμένο!) ❌       │
│                                                         │
│  → Γι' αυτό ασφαλίζουμε τα πάντα! 🔐                    │
└─────────────────────────────────────────────────────────┘
```

## Θέμα 1: Host Key Checking

### Τι είναι;
Όταν συνδέεσαι για πρώτη φορά σε server, το SSH αποθηκεύει το **fingerprint** του server. Σε επόμενες συνδέσεις, ελέγχει ότι το fingerprint **δεν άλλαξε**.

```bash
# Πρώτη σύνδεση
ssh ansible@192.212.104.27 -p 2022
# The authenticity of host '[192.212.104.27]:2022' can't be established.
# ED25519 key fingerprint is SHA256:xxxxxxxxxxx
# Are you sure you want to continue connecting (yes/no)?
# → Πατάς "yes" → αποθηκεύεται στο ~/.ssh/known_hosts
```

### Γιατί σημαντικό;
```
Αν ο fingerprint αλλάξει:
→ Κάποιος κάνει Man-in-the-Middle attack ❌
→ Ή ο server έγινε reinstall (νόμιμη αλλαγή)

Με host_key_checking = True:
→ Η Ansible αρνείται να συνδεθεί ✅
→ Σε προστατεύει από MITM attacks
```

### Σωστή ρύθμιση:

```ini
# ansible.cfg

[defaults]
# Για production: ΠΑΝΤΑ True
host_key_checking = True

# Για lab/testing: False (βολικό)
# host_key_checking = False
```

```bash
# Προσθήκη server στο known_hosts (πριν την πρώτη σύνδεση)
ssh-keyscan -p 2022 192.212.104.27 >> ~/.ssh/known_hosts

# Επαλήθευση fingerprint
ssh-keygen -lf ~/.ssh/known_hosts | grep 192.212.104.27
# 256 SHA256:xxxxx [192.212.104.27]:2022 (ED25519)

# Playbook για προσθήκη known_hosts σε νέους servers
- name: Add to known_hosts
  ansible.builtin.known_hosts:
    name: "[{{ ansible_host }}]:{{ ansible_port }}"
    key: "{{ lookup('pipe', 'ssh-keyscan -p ' + \
             ansible_port|string + ' ' + ansible_host) }}"
    state: present
```

## Θέμα 2: Bastion Server / Jump Host

### Τι είναι;
Ένας **ενδιάμεσος server** μέσω του οποίου περνάς για να φτάσεις στους managed servers. Οι managed servers **δεν είναι** απευθείας προσβάσιμοι από το internet.

```
Internet
    │
    ▼
┌───────────┐
│  Bastion  │  ← μόνο αυτός είναι exposed στο internet
│  Server   │     (port 2022, fail2ban, strict firewall)
└─────┬─────┘
      │  Private network
      ├──────────► web01 (192.168.1.10) ← δεν φαίνεται εξωτερικά
      ├──────────► db01  (192.168.1.20) ← δεν φαίνεται εξωτερικά
      └──────────► app01 (192.168.1.30) ← δεν φαίνεται εξωτερικά
```

### Ρύθμιση Bastion στην Ansible:

```ini
# ansible.cfg
[ssh_connection]
# Χρήση bastion server ως jump host
ssh_args = -C \
           -o ControlMaster=auto \
           -o ControlPersist=60s \
           -o ProxyJump=ansible@bastion.example.com:2022
```

```ini
# Ή στο inventory ανά host
[webservers]
web01 ansible_host=192.168.1.10 \
      ansible_ssh_common_args='-o ProxyJump=ansible@bastion.example.com:2022'
```

```bash
# ~/.ssh/config — πιο καθαρός τρόπος
Host bastion
    HostName bastion.example.com
    User ansible
    Port 2022
    IdentityFile ~/.ssh/id_ed25519

Host web01
    HostName 192.168.1.10
    User ansible
    Port 2022
    ProxyJump bastion          # ← μέσω bastion
    IdentityFile ~/.ssh/id_ed25519

Host db01
    HostName 192.168.1.20
    User ansible
    Port 2022
    ProxyJump bastion          # ← μέσω bastion
    IdentityFile ~/.ssh/id_ed25519
```

```yaml
# Playbook — διαφανές, δεν χρειάζεται αλλαγή!
- name: Configure web servers
  hosts: webservers             # ← η Ansible χρησιμοποιεί
  tasks:                        #   αυτόματα το ProxyJump
    - name: Install nginx
      ansible.builtin.package:
        name: nginx
        state: present
```

## Θέμα 3: SSH Tunneling

### Port Forwarding μέσω SSH:

```bash
# Local port forwarding
# Πρόσβαση σε remote service μέσω SSH tunnel
ssh -L 8080:localhost:80 \
    -i ~/.ssh/id_ed25519 \
    -p 2022 \
    ansible@192.212.104.27

# Τώρα: localhost:8080 → nextcloud:80

# Remote port forwarding
# Expose local service σε remote server
ssh -R 9090:localhost:9090 \
    -i ~/.ssh/id_ed25519 \
    -p 2022 \
    ansible@192.212.104.27
```

```yaml
# Με Ansible — δημιουργία tunnel για playbook
- name: Setup SSH tunnel
  hosts: localhost
  connection: local
  tasks:
    - name: Άνοιγμα SSH tunnel
      ansible.builtin.command:
        cmd: >
          ssh -fN
          -L 5432:localhost:5432
          -i /home/ansible/.ssh/id_ed25519
          -p 2022
          ansible@192.212.104.27
```

## Θέμα 4: Ansible Vault για SSH Keys

Αποθήκευση **ευαίσθητων δεδομένων** (passwords, keys) με κρυπτογράφηση:

```bash
# Κρυπτογράφηση private key password
ansible-vault encrypt_string 'MySecretPassword' \
    --name 'ansible_become_pass'

# Output:
# ansible_become_pass: !vault |
#           $ANSIBLE_VAULT;1.1;AES256
#           3861...

# Αποθήκευση σε group_vars
cat >> ~/ansible/inventory/group_vars/all.yml << 'EOF'
ansible_become_pass: !vault |
          $ANSIBLE_VAULT;1.1;AES256
          3861...
EOF
```

```bash
# Εκτέλεση με vault password
ansible-playbook playbooks/site.yml \
    --ask-vault-pass

# Ή με vault password file
echo "my_vault_password" > ~/.vault_pass
chmod 600 ~/.vault_pass
ansible-playbook playbooks/site.yml \
    --vault-password-file ~/.vault_pass
```

## Θέμα 5: Least Privilege — Ελάχιστα δικαιώματα

```yaml
---
# Βέλτιστη πρακτική: become μόνο όπου χρειάζεται

- name: Web Server Setup
  hosts: webservers
  become: false          # ← default: χωρίς sudo

  tasks:

    # Αυτό χρειάζεται sudo
    - name: Εγκατάσταση nginx
      ansible.builtin.package:
        name: nginx
        state: present
      become: true       # ← sudo μόνο εδώ

    # Αυτό ΔΕΝ χρειάζεται sudo
    - name: Έλεγχος nginx config
      ansible.builtin.command:
        cmd: nginx -t
      become: true       # ← sudo εδώ επίσης

    # Αυτό ΔΕΝ χρειάζεται sudo
    - name: Εμφάνιση nginx version
      ansible.builtin.command:
        cmd: nginx -v
                         # ← χωρίς sudo ✅

    # Γίνε συγκεκριμένος user (όχι root)
    - name: Δημιουργία app config
      ansible.builtin.copy:
        src: files/app.conf
        dest: /var/www/myapp/config.conf
      become: true
      become_user: www-data    # ← www-data, όχι root!
```

## Θέμα 6: Security Checklist για Manager Server

```bash
# 1. Έλεγχος SSH config
cat /etc/ssh/sshd_config | grep -E \
    "Port|PermitRoot|PasswordAuth|AllowUsers"
# Port 2022                    ✅
# PermitRootLogin no           ✅
# PasswordAuthentication no    ✅
# AllowUsers ansible           ✅

# 2. Έλεγχος firewall
sudo ferm -l
# ή
sudo ufw status

# 3. Έλεγχος fail2ban
sudo fail2ban-client status sshd

# 4. Έλεγχος authorized_keys
cat ~/.ssh/authorized_keys
# Μόνο τα keys που πρέπει να είναι εκεί!

# 5. Έλεγχος permissions
ls -la ~/.ssh/
# drwx------  .ssh/           (700) ✅
# -rw-------  id_ed25519      (600) ✅
# -rw-r--r--  id_ed25519.pub  (644) ✅
# -rw-------  authorized_keys (600) ✅
# -rw-r--r--  known_hosts     (644) ✅
# -rw-------  config          (600) ✅

# 6. Έλεγχος sudo config
sudo cat /etc/sudoers.d/ansible
# ansible ALL=(ALL) NOPASSWD: ALL ✅
```

## Playbook ασφάλειας Manager Server

```yaml
---
# secure-manager.yml
# Ασφάλεια του ίδιου του controller

- name: Secure Ansible Manager Server
  hosts: localhost
  connection: local
  become: true

  tasks:

    - name: Έλεγχος SSH permissions
      ansible.builtin.file:
        path: "{{ item.path }}"
        mode: "{{ item.mode }}"
        owner: ansible
        group: ansible
      loop:
        - { path: '/home/ansible/.ssh',
            mode: '0700' }
        - { path: '/home/ansible/.ssh/id_ed25519',
            mode: '0600' }
        - { path: '/home/ansible/.ssh/id_ed25519.pub',
            mode: '0644' }
        - { path: '/home/ansible/.ssh/authorized_keys',
            mode: '0600' }
        - { path: '/home/ansible/.ssh/config',
            mode: '0600' }

    - name: Έλεγχος ansible.cfg permissions
      ansible.builtin.file:
        path: /home/ansible/ansible/ansible.cfg
        mode: '0640'
        owner: ansible
        group: ansible

    - name: Έλεγχος log file permissions
      ansible.builtin.file:
        path: /home/ansible/ansible/ansible.log
        mode: '0640'
        owner: ansible
        group: ansible
        state: touch

    - name: Security report
      ansible.builtin.debug:
        msg:
          - "✅ SSH permissions: OK"
          - "✅ ansible.cfg: OK"
          - "✅ Log file: OK"
```

Εκτελώντας αυτό το playbook με `ansible-playbook playbooks/secure-manager.yml`, ο Controller σου θωρακίζεται αυτόματα.

## Η Δύναμη του SSH Config στην Ansible (Best Practice) 🚀

Το αρχείο `~/.ssh/config` στον Controller (Banana Pi) δεν είναι απλώς μια ευκολία για να γλιτώνουμε πληκτρολόγηση. Είναι μια **βέλτιστη πρακτική** που επιτρέπει τον πλήρη διαχωρισμό των τεχνικών λεπτομερειών σύνδεσης από την οργάνωση του Inventory μας.

### 🔒 Κρίσιμο Βήμα: Δικαιώματα Πρόσβασης (Permissions)

Πριν ξεκινήσουμε, πρέπει να διασφαλίσουμε ότι το αρχείο είναι ασφαλές. Ο SSH client θα αγνοήσει το αρχείο αν έχει "χαλαρά" δικαιώματα.

Εκτέλεσε στο τερματικό του Banana Pi:

```bash
# 1. Δημιουργία του αρχείου config (αν δεν υπάρχει)
touch ~/.ssh/config

# 2. Ρύθμιση αυστηρών δικαιωμάτων (πολύ σημαντικό για την ασφάλεια). Μόνο ο χρήστης σου μπορεί να διαβάζει/γράφει το αρχείο
chmod 600 ~/.ssh/config

# 3. Επεξεργασία του αρχείου
nano ~/.ssh/config
```
Μέσα στο αρχείο `config`, πρόσθεσε τα παρακάτω ως παράδειγμα, προσαρμόζοντας τις IPs:

```
# --- Γενικές Ρυθμίσεις για όλα τα hosts ---
Host *
    User ansible
    IdentityFile ~/.ssh/id_ed25519
    ServerAliveInterval 60
    ServerAliveCountMax 3

# --- RedHat VM ---
Host web-redhat
    HostName 192.168.1.10
    User ansible_user

# --- Debian VM ---
Host nextcloud
    HostName 192.212.104.27
    User ansible
    Port 2022
    IdentityFile ~/.ssh/id_ed25519

# --- openSUSE VM ---
Host app-suse
    HostName 192.168.1.12
    User sysadmin


```

### Γιατί το χρησιμοποιούμε στην Ansible;

Όταν η Ansible εκτελείται, ανατρέχει αυτόματα στις ρυθμίσεις του SSH του συστήματος. Αυτό μας επιτρέπει να διατηρούμε το αρχείο `hosts.ini` καθαρό και ευανάγνωστο.

#### ❌ Πώς είναι το Inventory ΧΩΡΙΣ SSH Config (Δύσκολο στη συντήρηση)

Αν δεν χρησιμοποιούσαμε το config, κάθε γραμμή στο Inventory θα έπρεπε να περιλαμβάνει όλες τις παραμέτρους:

```ini
[servers]
nextcloud ansible_host=192.212.104.27 ansible_user=ansible ansible_port=2022 ansible_ssh_private_key_file=~/.ssh/id_ed25519

```

#### ✅ Πώς είναι το Inventory ΜΕ SSH Config (Καθαρό & Επαγγελματικό)

Εφόσον οι λεπτομέρειες υπάρχουν ήδη στο `~/.ssh/config`, το Inventory γίνεται απλούστατο:

```ini
[servers]
nextcloud

```

> **Σημείωση για τον Μαθητή:** Στη δεύτερη περίπτωση, η Ansible "ρωτάει" το λειτουργικό σύστημα: *"Πώς συνδέομαι στο nextcloud;"*. Το σύστημα απαντάει με τις πληροφορίες από το SSH config και η σύνδεση γίνεται αυτόματα. Αν αύριο αλλάξεις την IP του server, θα τη διορθώσεις **μόνο σε ένα σημείο** (στο SSH config) και όχι σε όλα τα inventory files σου. 💡

## Σύνοψη 7.5

```
Ασφάλεια Σύνδεσης
├── Host Key Checking
│   ├── True  → production (MITM protection)
│   └── False → lab/testing (βολικό)
│
├── Bastion/Jump Host
│   ├── ProxyJump στο SSH config
│   └── Managed servers χωρίς public IP
│
├── SSH Tunneling
│   └── Πρόσβαση σε services μέσω SSH
│
├── Ansible Vault
│   └── Κρυπτογράφηση ευαίσθητων δεδομένων
│
├── Least Privilege
│   └── become: true μόνο όπου χρειάζεται
│
└── Security Checklist
    ├── SSH config (port, root, password)
    ├── Firewall (ferm/ufw)
    ├── fail2ban
    ├── authorized_keys
    └── Permissions (700/600/644)
```
