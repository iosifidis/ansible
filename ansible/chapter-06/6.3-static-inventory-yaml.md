# 6.3 Static Inventory — YAML Format 📄

## Γιατί YAML Format;

Το YAML format είναι **πιο δομημένο** από το INI και προτιμάται όταν:

```
✅ Έχεις πολύπλοκη ιεραρχία groups
✅ Θέλεις consistency με τα playbooks (όλα σε YAML)
✅ Έχεις πολλές μεταβλητές ανά host/group
✅ Χρησιμοποιείς version control (git) — πιο ευανάγνωστο diff
```

---

## Βασική δομή

Το YAML inventory έχει **πάντα** αυτή τη βασική δομή:

```yaml
# hosts.yml
---
all:                        # ← το root group (πάντα "all")
  hosts:                    # ← απευθείας hosts στο "all"
    myserver:
      ansible_host: 192.168.1.10

  children:                 # ← child groups του "all"
    webservers:             # ← ένα group
      hosts:                # ← hosts αυτού του group
        web01:
          ansible_host: 192.168.1.11
        web02:
          ansible_host: 192.168.1.12

    dbservers:              # ← άλλο group
      hosts:
        db01:
          ansible_host: 192.168.1.20
```

> 📝 **Σημαντική διαφορά από INI:**
> ```
> INI  → [group] είναι η δήλωση group
> YAML → children: είναι η δήλωση groups
>        hosts:    είναι η δήλωση hosts
> ```

---

## Σύγκριση INI vs YAML

Το ίδιο inventory και στις δύο μορφές:

```ini
# INI format
[webservers]
web01 ansible_host=192.168.1.10 ansible_port=2022
web02 ansible_host=192.168.1.11 ansible_port=2022

[webservers:vars]
http_port=80

[dbservers]
db01 ansible_host=192.168.1.20

[production:children]
webservers
dbservers

[all:vars]
ansible_user=ansible
```

```yaml
# YAML format — ακριβώς το ίδιο!
---
all:
  vars:                           # [all:vars]
    ansible_user: ansible

  children:
    production:                   # [production:children]
      children:
        webservers:               # [webservers]
          vars:                   # [webservers:vars]
            http_port: 80
          hosts:
            web01:                # web01
              ansible_host: 192.168.1.10
              ansible_port: 2022
            web02:                # web02
              ansible_host: 192.168.1.11
              ansible_port: 2022

        dbservers:                # [dbservers]
          hosts:
            db01:                 # db01
              ansible_host: 192.168.1.20
```

## Host Variables στο YAML

```yaml
---
all:
  children:
    webservers:
      hosts:

        web01:
          # ── Σύνδεση ──────────────────────────
          ansible_host: 192.168.1.10
          ansible_port: 2022
          ansible_user: ansible

          # ── Custom μεταβλητές ─────────────────
          server_role: primary
          nginx_worker_processes: 4
          ssl_enabled: true

        web02:
          ansible_host: 192.168.1.11
          ansible_port: 2022
          ansible_user: ansible

          # Διαφορετικές τιμές για web02
          server_role: secondary
          nginx_worker_processes: 2
          ssl_enabled: true
```

## Group Variables στο YAML

```yaml
---
all:
  # ── Global vars (για ΟΛΟΥΣ) ───────────────────
  vars:
    ansible_user:                 ansible
    ansible_ssh_private_key_file: /home/ansible/.ssh/id_ed25519
    ansible_become:               true
    ansible_become_method:        sudo
    system_timezone:              "Europe/Athens"

  children:
    webservers:
      # ── Group vars (για webservers) ───────────
      vars:
        http_port:  80
        https_port: 443
        app_env:    production

      hosts:
        web01:
          ansible_host: 192.168.1.10
        web02:
          ansible_host: 192.168.1.11

    dbservers:
      # ── Group vars (για dbservers) ────────────
      vars:
        db_port:         5432
        db_name:         myapp
        max_connections: 100

      hosts:
        db01:
          ansible_host: 192.168.1.20
          # ── Host var (override group var) ─────
          max_connections: 200   # ← override!
```

> 💡 **Προτεραιότητα μεταβλητών:**
> ```
> Host vars      → υψηλότερη προτεραιότητα
>     ↓
> Group vars     → χαμηλότερη προτεραιότητα
>     ↓
> All vars       → χαμηλότερη όλων
> ```
> Στο παράδειγμα: `db01` έχει `max_connections=200` (override), 
> ενώ `db02` θα έχει `max_connections=100` (από το group).

## Nested Groups στο YAML

```yaml
---
all:
  children:

    # ── Leaf groups (περιέχουν hosts) ────────────
    webservers:
      hosts:
        web01:
          ansible_host: 192.168.1.10
        web02:
          ansible_host: 192.168.1.11

    dbservers:
      hosts:
        db01:
          ansible_host: 192.168.1.20

    monitoring:
      hosts:
        grafana01:
          ansible_host: 192.168.1.30

    # ── Parent groups (περιέχουν groups) ─────────
    production:
      children:
        webservers:
        dbservers:
        monitoring:

    # ── Distro groups ─────────────────────────────
    debian_based:
      hosts:
        web01:
        web02:
        db01:

    redhat_based:
      hosts:
        grafana01:

    # ── Meta group ────────────────────────────────
    all_managed:
      children:
        debian_based:
        redhat_based:
```

> ⚠️ **Προσοχή στο YAML:** Όταν αναφέρεις host που έχεις ήδη ορίσει αλλού, **δεν χρειάζεται** να ξαναγράψεις τις μεταβλητές του. Απλά γράφεις το όνομά του:
```yaml
debian_based:
  hosts:
    web01:    # ← κενό! Οι vars ορίστηκαν στο webservers group
    web02:
```

## Πλήρες παράδειγμα — Real World YAML

```yaml
---
# ============================================================
# Production Inventory (YAML format)
# ============================================================
all:

  # ── Global Variables ──────────────────────────
  vars:
    ansible_user:                 ansible
    ansible_ssh_private_key_file: /home/ansible/.ssh/id_ed25519
    ansible_become:               true
    ansible_become_method:        sudo
    ansible_become_user:          root
    system_timezone:              "Europe/Athens"

  children:

    # ── Controller ────────────────────────────────
    controller:
      hosts:
        localhost:
          ansible_connection: local

    # ── Web Servers ───────────────────────────────
    webservers:
      vars:
        http_port:  80
        https_port: 443
      hosts:
        web01:
          ansible_host: 192.168.1.10
          ansible_port: 2022
        web02:
          ansible_host: 192.168.1.11
          ansible_port: 2022

    # ── Database Servers ──────────────────────────
    dbservers:
      vars:
        db_port: 5432
      hosts:
        db01:
          ansible_host: 192.168.1.20
          ansible_port: 2022
        db02:
          ansible_host: 192.168.1.21
          ansible_port: 2022

    # ── Distro Groups ─────────────────────────────
    debian_based:
      hosts:
        web01:
        web02:
        db01:

    redhat_based:
      hosts:
        db02:

    opensuse_based:

    # ── Nested Groups ─────────────────────────────
    all_managed:
      children:
        debian_based:
        redhat_based:
        opensuse_based:

    production:
      children:
        webservers:
        dbservers:
```

## INI vs YAML — Πότε να διαλέξεις τι

```
┌─────────────────────┬───────────────┬───────────────────┐
│ Κριτήριο            │ INI           │ YAML              │
├─────────────────────┼───────────────┼───────────────────┤
│ Απλότητα            │ ⭐⭐⭐        │ ⭐⭐              │
│ Πολύπλοκη ιεραρχία  │ ⭐⭐          │ ⭐⭐⭐            │
│ Πολλές μεταβλητές   │ ⭐⭐          │ ⭐⭐⭐            │
│ Consistency YAML    │ ❌            │ ✅                │
│ Εκμάθηση            │ ✅            │ ✅                │
│ Production          │ ✅            │ ✅                │
└─────────────────────┴───────────────┴───────────────────┘
```

> 💡 **Η πρότασή μου:** Χρησιμοποίησε **INI** για αρχή (απλούστερο) και **YAML** όταν η υποδομή σου μεγαλώσει ή χρειαστείς πολλές μεταβλητές.

---

## Σύνοψη 6.3

```
YAML Inventory
├── Root: always "all"
├── Δομή: all → vars + children
├── children → groups
├── hosts → servers ανά group
├── vars → μεταβλητές ανά group ή host
├── Nested: children μέσα σε children
└── Προτεραιότητα vars:
    host vars > group vars > all vars
```
