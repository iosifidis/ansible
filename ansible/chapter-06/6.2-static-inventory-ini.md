# 6.2 Static Inventory — INI Format 📄

## Γιατί INI Format;

Το INI format είναι το **πιο διαδεδομένο** format για static inventory γιατί:
- Είναι **απλό** και κατανοητό
- Μοιάζει με το `ansible.cfg` που ήδη ξέρουμε
- **Λιγότερος κώδικας** από το YAML για απλές υποδομές

---

## Βασική δομή

```ini
# Μεμονωμένοι hosts (χωρίς group)
# Ανήκουν αυτόματα στο [ungrouped]
192.168.1.10
myserver.example.com

# ── Group ────────────────────────────────────
[webservers]
web01.example.com
web02.example.com
192.168.1.20

# ── Group με μεταβλητές ανά host ─────────────
[dbservers]
db01 ansible_host=192.168.1.30 ansible_port=2022
db02 ansible_host=192.168.1.31 ansible_port=2022
```

---

## Host Groups — Ομαδοποίηση

Τα groups μας επιτρέπουν να **στοχεύουμε** συγκεκριμένους servers:

```ini
[webservers]
web01 ansible_host=192.168.1.10
web02 ansible_host=192.168.1.11
web03 ansible_host=192.168.1.12

[dbservers]
db01 ansible_host=192.168.1.20
db02 ansible_host=192.168.1.21

[monitoring]
grafana01 ansible_host=192.168.1.30
```

```bash
# Εκτέλεση μόνο σε webservers
ansible webservers -m ping

# Εκτέλεση μόνο σε dbservers
ansible dbservers -m ping

# Εκτέλεση σε όλους
ansible all -m ping
```

## Nested Groups — Groups μέσα σε Groups

Η πιο ισχυρή δυνατότητα του inventory:

```ini
[webservers]
web01 ansible_host=192.168.1.10
web02 ansible_host=192.168.1.11

[dbservers]
db01 ansible_host=192.168.1.20
db02 ansible_host=192.168.1.21

[monitoring]
grafana01 ansible_host=192.168.1.30

# ── Nested Groups ─────────────────────────────
# Το :children δηλώνει ότι περιέχει groups
[production:children]
webservers
dbservers
monitoring

# Μπορείς να φτιάξεις και άλλα nested groups
[databases:children]
dbservers

# Και να τα φωλιάσεις περαιτέρω!
[all_servers:children]
production
databases
```

```bash
# Εκτέλεση σε όλα τα production systems
ansible production -m ping
# → web01, web02, db01, db02, grafana01

# Εκτέλεση μόνο σε databases
ansible databases -m ping
# → db01, db02
```

> 📝 **Σημείωση για τον Μαθητή:** Το `:children` είναι **keyword** της Ansible — δεν είναι τυχαίο όνομα. Λέει στην Ansible ότι αυτό το group περιέχει **άλλα groups** και όχι απευθείας hosts.

## Host Ranges — Σύντομη γραφή

Όταν έχεις πολλούς servers με παρόμοια ονόματα:

```ini
# Αριθμητικά ranges
[webservers]
web[01:10].example.com    # web01, web02, ... web10

[dbservers]
db[1:5].example.com       # db1, db2, db3, db4, db5

# Αλφαβητικά ranges
[appservers]
app[a:f].example.com      # appa, appb, appc, appd, appe, appf

# Με custom step
[cacheservers]
cache[01:10:2].example.com  # cache01, cache03, cache05, cache07, cache09
#           ↑
#           step = 2
```

```bash
# Επαλήθευση — δες ποιοι hosts δημιουργήθηκαν
ansible-inventory --graph

# @webservers:
# |--web01.example.com
# |--web02.example.com
# ...
# |--web10.example.com
```

## Group Variables στο INI

```ini
[webservers]
web01 ansible_host=192.168.1.10
web02 ansible_host=192.168.1.11

# Μεταβλητές για ΟΛΟΥΣ τους webservers
# Το :vars δηλώνει ότι αυτές είναι μεταβλητές του group
[webservers:vars]
http_port=80
https_port=443
app_env=production
nginx_worker_processes=4

[dbservers]
db01 ansible_host=192.168.1.20

[dbservers:vars]
db_port=5432
db_name=myapp
max_connections=100

# Μεταβλητές για ΟΛΟΥΣ τους hosts
[all:vars]
ansible_user                 = ansible
ansible_ssh_private_key_file = /home/ansible/.ssh/id_ed25519
ansible_become               = true
ansible_become_method        = sudo
```

## Πλήρες παράδειγμα — Real World

```ini
# ============================================================
# Production Inventory
# ============================================================

# ── Controllers ───────────────────────────────
[controller]
localhost ansible_connection=local

# ── Web Servers ───────────────────────────────
[webservers]
web01 ansible_host=192.168.1.10 ansible_port=2022
web02 ansible_host=192.168.1.11 ansible_port=2022

# ── Database Servers ──────────────────────────
[dbservers]
db01  ansible_host=192.168.1.20 ansible_port=2022
db02  ansible_host=192.168.1.21 ansible_port=2022

# ── Debian based ──────────────────────────────
[debian_based]
web01
web02
db01

# ── RedHat based ──────────────────────────────
[redhat_based]
db02

# ── openSUSE based ────────────────────────────
[opensuse_based]
# προς το παρόν κενό

# ── Nested Groups ─────────────────────────────
[all_managed:children]
debian_based
redhat_based
opensuse_based

[production:children]
webservers
dbservers

# ── Global Variables ──────────────────────────
[all:vars]
ansible_user                 = ansible
ansible_ssh_private_key_file = /home/ansible/.ssh/id_ed25519
ansible_become               = true
ansible_become_method        = sudo

# ── Group Variables ───────────────────────────
[webservers:vars]
http_port  = 80
https_port = 443

[dbservers:vars]
db_port = 5432
```

## Χρήσιμα Patterns για εκτέλεση

```bash
# Ένα group
ansible webservers -m ping

# Πολλά groups
ansible webservers,dbservers -m ping

# Όλα εκτός από ένα group
ansible all,!monitoring -m ping

# Intersection (hosts που ανήκουν και στα δύο groups)
ansible webservers:&debian_based -m ping

# Συγκεκριμένος host
ansible web01 -m ping

# Pattern με wildcard
ansible web* -m ping
# → web01, web02 κλπ
```

## Σύνοψη 6.2

```
INI Inventory
├── Βασική δομή: [group] + hosts
├── Host groups    → [webservers], [dbservers]
├── Nested groups  → [production:children]
├── Group vars     → [webservers:vars]
├── Global vars    → [all:vars]
├── Host ranges    → web[01:10].example.com
└── Patterns:
    ├── all        → όλοι
    ├── group1,group2 → πολλά groups
    ├── all,!group → εξαίρεση
    └── g1:&g2     → intersection
```
