# 14.4 Tag Strategies 🎯

## Γιατί χρειάζεται στρατηγική;

Χωρίς στρατηγική, τα tags γίνονται **χάος**:

```yaml
# ❌ ΧΩΡΙΣ στρατηγική — ακατάστατο
tasks:
  - name: Install nginx
    tags: [nginx, install, web, server, packages, setup, n]

  - name: Configure nginx
    tags: [nginx_config, conf, configure, web_config, cfg]

  - name: Start nginx
    tags: [nginx, start, service, run, go]
```

```yaml
# ✅ ΜΕ στρατηγική — καθαρό και προβλέψιμο
tasks:
  - name: Install nginx
    tags: [install, nginx]

  - name: Configure nginx
    tags: [config, nginx]

  - name: Start nginx
    tags: [service, nginx]
```

---

## Στρατηγική 1: Action-based Tags

Οργάνωση βάσει **τι κάνει** το task:

```yaml
# Tags βάσει ενέργειας
tasks:

  # ── install → εγκατάσταση packages ───────
  - name: Install nginx
    ansible.builtin.package:
      name:  nginx
      state: present
    tags: [install, nginx]

  - name: Install PHP
    ansible.builtin.package:
      name:  php
      state: present
    tags: [install, php]

  # ── config → ρύθμιση αρχείων ─────────────
  - name: Configure nginx
    ansible.builtin.template:
      src:  templates/nginx.conf.j2
      dest: /etc/nginx/nginx.conf
    tags: [config, nginx]

  - name: Configure PHP
    ansible.builtin.template:
      src:  templates/php.ini.j2
      dest: /etc/php/php.ini
    tags: [config, php]

  # ── service → διαχείριση services ────────
  - name: Start nginx
    ansible.builtin.service:
      name:  nginx
      state: started
    tags: [service, nginx]

  # ── deploy → deployment tasks ─────────────
  - name: Deploy application
    ansible.builtin.copy:
      src:  dist/myapp.tar.gz
      dest: /opt/myapp/
    tags: [deploy, app]

  # ── verify → επαλήθευση ───────────────────
  - name: Check nginx
    ansible.builtin.uri:
      url: http://localhost
    tags: [verify, nginx]
```

```bash
# Χρήση:
ansible-playbook site.yml --tags install    # μόνο εγκαταστάσεις
ansible-playbook site.yml --tags config     # μόνο ρυθμίσεις
ansible-playbook site.yml --tags deploy     # μόνο deployment
ansible-playbook site.yml --tags verify     # μόνο επαλήθευση
```

## Στρατηγική 2: Component-based Tags

Οργάνωση βάσει **ποιο component** αφορά:

```yaml
tasks:

  # ── nginx component ───────────────────────
  - name: Install nginx
    ansible.builtin.package:
      name: nginx
      state: present
    tags: nginx

  - name: Configure nginx
    ansible.builtin.template:
      src:  templates/nginx.conf.j2
      dest: /etc/nginx/nginx.conf
    tags: nginx

  - name: Start nginx
    ansible.builtin.service:
      name:  nginx
      state: started
    tags: nginx

  # ── php component ─────────────────────────
  - name: Install PHP
    ansible.builtin.package:
      name: php
      state: present
    tags: php

  - name: Configure PHP
    ansible.builtin.template:
      src:  templates/php.ini.j2
      dest: /etc/php/php.ini
    tags: php

  # ── database component ────────────────────
  - name: Install PostgreSQL
    ansible.builtin.package:
      name: postgresql
      state: present
    tags: database

  - name: Configure PostgreSQL
    ansible.builtin.template:
      src:  templates/postgresql.conf.j2
      dest: /etc/postgresql/postgresql.conf
    tags: database
```

```bash
# Χρήση:
ansible-playbook site.yml --tags nginx      # μόνο nginx
ansible-playbook site.yml --tags php        # μόνο PHP
ansible-playbook site.yml --tags database   # μόνο database
```

## Στρατηγική 3: Hybrid (Συνδυασμός) ✅

Η **βέλτιστη πρακτική** — συνδυάζει action + component:

```yaml
tasks:

  # ── Format: action + component ────────────
  - name: Install nginx
    ansible.builtin.package:
      name:  nginx
      state: present
    tags:
      - install     # ← action
      - nginx       # ← component
      - packages    # ← category

  - name: Configure nginx
    ansible.builtin.template:
      src:  templates/nginx.conf.j2
      dest: /etc/nginx/nginx.conf
    tags:
      - config      # ← action
      - nginx       # ← component

  - name: Install PHP
    ansible.builtin.package:
      name:  php
      state: present
    tags:
      - install     # ← action
      - php         # ← component
      - packages    # ← category

  - name: Configure PHP
    ansible.builtin.template:
      src:  templates/php.ini.j2
      dest: /etc/php/php.ini
    tags:
      - config      # ← action
      - php         # ← component

  - name: Deploy application
    ansible.builtin.copy:
      src:  dist/myapp/
      dest: /opt/myapp/
    tags:
      - deploy      # ← action
      - app         # ← component

  - name: Verify deployment
    ansible.builtin.uri:
      url: http://localhost
    tags:
      - verify      # ← action
      - app         # ← component
      - always      # ← special: πάντα τρέχει
```

```bash
# Ευέλικτη χρήση:
ansible-playbook site.yml --tags install    # όλες οι εγκαταστάσεις
ansible-playbook site.yml --tags nginx      # όλα τα nginx tasks
ansible-playbook site.yml --tags "install,nginx"  # nginx install μόνο
ansible-playbook site.yml --skip-tags packages    # χωρίς packages
```

## Στρατηγική 4: Environment-based Tags

Tags για **διαφορετικά environments**:

```yaml
tasks:

  # ── Production only ───────────────────────
  - name: Enable production optimizations
    ansible.builtin.template:
      src:  templates/production.conf.j2
      dest: /etc/myapp/production.conf
    tags:
      - production
      - config

  # ── Staging only ──────────────────────────
  - name: Enable debug mode
    ansible.builtin.lineinfile:
      path:  /etc/myapp/app.conf
      line:  "DEBUG=true"
    tags:
      - staging
      - debug
      - never      # ← δεν τρέχει by default!

  # ── Development only ──────────────────────
  - name: Install dev tools
    ansible.builtin.package:
      name: "{{ item }}"
      state: present
    loop: [gdb, valgrind, strace]
    tags:
      - development
      - never      # ← μόνο όταν ζητηθεί explicitly
```

```bash
# Production deployment
ansible-playbook site.yml --skip-tags "staging,development"

# Staging deployment
ansible-playbook site.yml --skip-tags "production,development"

# Dev environment
ansible-playbook site.yml --tags "development,never"
```

## Στρατηγική 5: CI/CD Pipeline Tags

```yaml
tasks:

  # ── Stage 1: Prepare ──────────────────────
  - name: Update packages
    ansible.builtin.package:
      name:  "*"
      state: latest
    tags: [prepare, update]

  - name: Install dependencies
    ansible.builtin.package:
      name:  "{{ item }}"
      state: present
    loop: "{{ dependencies }}"
    tags: [prepare, install]

  # ── Stage 2: Configure ────────────────────
  - name: Deploy configs
    ansible.builtin.template:
      src:  "templates/{{ item }}.j2"
      dest: "/etc/myapp/{{ item }}"
    loop: [app.conf, db.conf, cache.conf]
    tags: [configure, config]

  # ── Stage 3: Deploy ───────────────────────
  - name: Deploy application
    ansible.builtin.copy:
      src:  dist/
      dest: /opt/myapp/
    tags: [deploy]

  - name: Restart services
    ansible.builtin.service:
      name:  myapp
      state: restarted
    tags: [deploy, restart]

  # ── Stage 4: Verify ───────────────────────
  - name: Health check
    ansible.builtin.uri:
      url:         http://localhost/health
      status_code: 200
    tags: [verify, health]
    retries: 5
    delay:   10

  - name: Smoke tests
    ansible.builtin.command:
      cmd: /usr/local/bin/smoke_test.sh
    tags: [verify, test]
    changed_when: false
```

```bash
# CI/CD Pipeline stages:
# Stage 1
ansible-playbook site.yml --tags prepare

# Stage 2
ansible-playbook site.yml --tags configure

# Stage 3
ansible-playbook site.yml --tags deploy

# Stage 4
ansible-playbook site.yml --tags verify

# Full pipeline
ansible-playbook site.yml
```

## Tag Naming Conventions

```
✅ ΚΑΛΑ ονόματα tags:
├── install, config, deploy, verify, update
├── nginx, php, mysql, redis, app
├── security, packages, service
├── production, staging, development
└── always, never (special)

❌ ΚΑΚΑ ονόματα tags:
├── n, cfg, inst, dep     ← πολύ σύντομα
├── install_nginx_now     ← πολύ συγκεκριμένο
├── doTheThing            ← camelCase
├── my-tag                ← παύλα (αποφύγετε)
└── 1st_task              ← αριθμός στην αρχή
```

## Ανακεφαλαίωση στρατηγικών

```
┌──────────────────┬───────────────────────────────────┐
│ Στρατηγική       │ Πότε να Χρησιμοποιείς             │
├──────────────────┼───────────────────────────────────┤
│ Action-based     │ Απλά playbooks, λίγα components   │
│ Component-based  │ Πολλά components, λίγες actions   │
│ Hybrid ✅        │ Παραγωγικά playbooks (συνιστάται) │
│ Environment      │ Multi-environment deployments     │
│ CI/CD Pipeline   │ Automated deployments             │
└──────────────────┴───────────────────────────────────┘
```

## Σύνοψη 14.4

```
Tag Strategies
├── Action-based:   install, config, deploy, verify
├── Component-based: nginx, php, database, app
├── Hybrid ✅:       action + component (βέλτιστο)
│   └── tags: [install, nginx]
├── Environment:    production, staging, never
└── CI/CD:          prepare, configure, deploy, verify

Naming conventions:
├── snake_case ή lowercase
├── Σύντομο αλλά περιγραφικό
├── Χωρίς παύλες
└── Χρήση special tags:
    ├── always → critical tasks (facts, reports)
    └── never  → επικίνδυνα/debug tasks
```
