# 18.5 Strategy — Στρατηγική εκτέλεσης 🎯

## Τι είναι η Strategy

Η **strategy** καθορίζει **πώς η Ansible διανέμει tasks** στα hosts. Είναι η «φιλοσοφία» εκτέλεσης.

```
Ansible strategies:

├── linear (default)
│   └── Όλοι περιμένουν τον πιο αργό
│
├── free
│   └── Κάθε host τρέχει στη δική του ταχύτητα
│
└── host_pinned
    └── Ένα host τελειώνει ΟΛΑ τα tasks
        πριν ξεκινήσει το επόμενο
```

---

## linear — Η default strategy

Στο `linear`, **κάθε task περιμένει** να ολοκληρωθεί σε **όλα** τα hosts πριν προχωρήσει στο επόμενο:

```
hosts: web-01, web-02, web-03
strategy: linear (default)

Task 1: Install nginx
  web-01 ──2s──► ✅ (τελείωσε)  ← ΠΕΡΙΜΕΝΕΙ web-02, web-03
  web-02 ──5s──► ✅ (τελείωσε)  ← ΠΕΡΙΜΕΝΕΙ web-03
  web-03 ──8s──► ✅ (τελείωσε)
                      │
                      ▼ (8s συνολικά — ο πιο αργός!)
Task 2: Copy config
  web-01 ──1s──► ✅
  web-02 ──1s──► ✅
  web-03 ──1s──► ✅
                      │
                      ▼ (1s)
Task 3: Start service
  ...
```

**Πλεονεκτήματα linear:**
```
✅ Προβλέψιμη σειρά εκτέλεσης
✅ Εύκολο debugging (ξέρεις πού βρίσκεσαι)
✅ Handlers εκτελούνται με σωστή σειρά
✅ Κατάλληλο για deployments με dependencies
```

---

## free — Ανεξάρτητη εκτέλεση

Στο `free`, κάθε host **τρέχει ανεξάρτητα** — δεν περιμένει τους άλλους:

```
hosts: web-01, web-02, web-03
strategy: free

web-01 (γρήγορος): Task1 → Task2 → Task3 → ✅ ΤΕΛΟΣ
web-02 (μέτριος):  Task1 →    Task2    → Task3 → ✅
web-03 (αργός):    Task1 →       Task2       → Task3 → ✅

→ web-01 τελειώνει πολύ νωρίτερα!
  Δεν χάνει χρόνο περιμένοντας τους αργούς.
```

```yaml
---
- name: Free Strategy Demo
  hosts: all
  strategy: free    # ← ορισμός στο play level
  gather_facts: true

  tasks:
    - name: Package update
      ansible.builtin.apt:
        upgrade: safe
      # ← web-01 αρχίζει Task 2 μόλις τελειώσει,
      #    χωρίς να περιμένει web-02, web-03!
```

**Πλεονεκτήματα free:**
```
✅ Γρηγορότερο συνολικά
✅ Γρήγοροι hosts δεν "τιμωρούνται" από αργούς
✅ Κατάλληλο για ανεξάρτητες εργασίες
   (π.χ. package updates σε πολλά servers)
```

**Μειονεκτήματα free:**
```
❌ Δύσκολο debugging
❌ Handlers μπορεί να εκτελεστούν "νωρίς"
❌ Tasks με dependencies δεν δουλεύουν σωστά
❌ Μη προβλέψιμη σειρά
```

## host_pinned — Ένα host τελειώνει πρώτα

Με `host_pinned`, η Ansible τελειώνει **όλο το play** για ένα host πριν αρχίσει για το επόμενο:

```
hosts: web-01, web-02, web-03
strategy: host_pinned

web-01: Task1 → Task2 → Task3 → ✅ ΤΕΛΟΣ
                                      │
                                      ▼
web-02: Task1 → Task2 → Task3 → ✅ ΤΕΛΟΣ
                                      │
                                      ▼
web-03: Task1 → Task2 → Task3 → ✅ ΤΕΛΟΣ
```

> 📝 **Διαφορά από serial:**
> ```
> serial: 1 → ολοκλήρωση play ανά host (αλλά μέσω batch)
> host_pinned → παρόμοιο, αλλά πιο αυστηρό
> ```

## Ρύθμιση strategy

### Στο play level (προτιμητέο)

```yaml
---
- name: Linear play (default)
  hosts: webservers
  strategy: linear    # ← ρητός ορισμός (ή παράλειψη)

  tasks:
    # ...

---
- name: Free play
  hosts: updateservers
  strategy: free      # ← ανεξάρτητη εκτέλεση

  tasks:
    # ...
```

### Στο ansible.cfg (global default)

```ini
# ansible.cfg
[defaults]
strategy = free    # ← αλλάζει default για ΟΛΑ τα plays
```

> ⚠️ **Προσοχή:** Αλλαγή του global strategy μπορεί να σπάσει plays που βασίζονται στο linear. Προτίμα ορισμό ανά play.

## Σύγκριση: Πότε να χρησιμοποιείς τι

```
┌─────────────────────────────────────────────────────────┐
│  Σενάριο                          │  Strategy           │
├─────────────────────────────────────────────────────────┤
│  Web app deployment               │  linear + serial    │
│  (tasks εξαρτώνται μεταξύ τους)   │                     │
├─────────────────────────────────────────────────────────┤
│  OS package updates               │  free               │
│  (ανεξάρτητα ανά host)            │                     │
├─────────────────────────────────────────────────────────┤
│  Database migrations              │  linear, serial: 1  │
│  (μία τη φορά!)                   │                     │
├─────────────────────────────────────────────────────────┤
│  Security patching (πολλά hosts)  │  free               │
│                                   │                     │
├─────────────────────────────────────────────────────────┤
│  Config management                │  linear (default)   │
│  (reproducible state)             │                     │
├─────────────────────────────────────────────────────────┤
│  Zero-downtime rolling update     │  linear + serial    │
│                                   │  + pre/post_tasks   │
└─────────────────────────────────────────────────────────┘
```

## run_once — Εκτέλεση σε ένα μόνο host

Το `run_once` δεν είναι strategy, αλλά συνδέεται με αυτή τη θεματική:

```yaml
tasks:

  # ── Εκτελείται μόνο σε 1 host ────────────
  - name: Database migration (μόνο μία φορά!)
    ansible.builtin.command:
      cmd: /opt/app/manage.py migrate
    run_once: true     # ← τρέχει στον ΠΡΩΤΟ host
                       #   των ansible_play_hosts
    changed_when: true

  # ── Με delegate_to — σε συγκεκριμένο host ─
  - name: Update DNS record (μόνο μία φορά)
    ansible.builtin.uri:
      url:    "https://dns.example.com/update"
      method: POST
    run_once:    true
    delegate_to: localhost    # ← τρέχει τοπικά (controller)
```

> 💡 **run_once vs delegate_to localhost:**
> ```
> run_once:              εκτελείται στον 1ο managed host
> delegate_to: localhost: εκτελείται στον Ansible controller
> Συνδυασμός:            εκτελείται τοπικά, μία φορά ✅
> ```

## Callback plugins — Ομορφαίνουν το output

Τα **callback plugins** αλλάζουν τον τρόπο εμφάνισης αποτελεσμάτων. Χρήσιμα για performance monitoring:

```ini
# ansible.cfg
[defaults]
# Ευανάγνωστο output ανά host
stdout_callback = yaml

# Ή minimal (πιο σύντομο)
stdout_callback = minimal

# Ή timer (εμφανίζει χρόνο εκτέλεσης)
callback_whitelist = timer, profile_tasks
```

```bash
# Με profile_tasks — βλέπεις ποια tasks είναι αργά:
# ...
# TASK [Install nginx] *****
# ok: [web-01]
# ...
# PLAY RECAP *****
#
# Playbook run took 0 days, 0 hours, 2 minutes, 34 seconds
#
# Thursday 09 August 2026  21:00:01 +0300 (0:02:34.123)  *****
# ================================================================
# Install nginx          : 0:00:45.234  ← 45s!!! Αργό!
# Copy config            : 0:00:02.100
# Start service          : 0:00:01.800
```

## Σύνοψη 18.5

```
Strategy — Στρατηγική εκτέλεσης
│
├── linear (default):
│   ├── Task N → ολοκλήρωση σε ΟΛΟΥΣ → Task N+1
│   ├── Προβλέψιμο, ασφαλές
│   └── Χρήση: deployments, config management
│
├── free:
│   ├── Κάθε host τρέχει ανεξάρτητα
│   ├── Γρηγορότερο συνολικά
│   └── Χρήση: updates, patching, ανεξάρτητα tasks
│
├── host_pinned:
│   └── Ένα host τελειώνει ΟΛΑ → επόμενο
│
├── run_once:
│   └── Εκτελείται σε 1 μόνο host
│       (+ delegate_to: localhost → τοπικά)
│
└── Callback plugins:
    ├── profile_tasks → χρόνος ανά task
    └── timer         → συνολικός χρόνος
```
