# 18.1 Πώς εκτελεί η Ansible tasks ⚡

## Η βασική αρχή

Πριν μιλήσουμε για performance, πρέπει να καταλάβουμε **πώς εκτελεί η Ansible tasks** από προεπιλογή.

> 📝 **Αναλογία:** Σκέψου μια ορχήστρα:
> ```
> Linear (default):
> Όλοι οι μουσικοί παίζουν την ίδια νότα ταυτόχρονα.
> Μόλις τελειώσουν ΟΛΟι → επόμενη νότα.
>
> Free strategy:
> Κάθε μουσικός παίζει τη δική του ταχύτητα.
> Δεν περιμένει κανέναν.
> ```

---

## Linear execution — Η default συμπεριφορά

Η Ansible εκτελεί tasks με βάση τον **"task-by-task across all hosts"** κανόνα:

```
Παράδειγμα: 4 hosts, 3 tasks

  Task 1: Install nginx
  ┌─────────┬─────────┬─────────┬─────────┐
  │ host-01 │ host-02 │ host-03 │ host-04 │
  │   ✅    │   ✅    │   ✅    │   ✅    │  ← όλοι τελείωσαν
  └─────────┴─────────┴─────────┴─────────┘
                    │
                    ▼
  Task 2: Copy config
  ┌─────────┬─────────┬─────────┬─────────┐
  │ host-01 │ host-02 │ host-03 │ host-04 │
  │   ✅    │   ✅    │   ✅    │   ✅    │  ← όλοι τελείωσαν
  └─────────┴─────────┴─────────┴─────────┘
                    │
                    ▼
  Task 3: Start service
  ┌─────────┬─────────┬─────────┬─────────┐
  │ host-01 │ host-02 │ host-03 │ host-04 │
  │   ✅    │   ✅    │   ✅    │   ✅    │
  └─────────┴─────────┴─────────┴─────────┘

Κανόνας: Task N+1 ξεκινά ΜΟΝΟ αφού ολοκληρωθεί
          το Task N σε ΟΛΑ τα hosts.
```

## Ο ρόλος των forks

Η Ansible δεν στέλνει εντολές σε ένα host τη φορά — στέλνει ταυτόχρονα σε **N hosts παράλληλα**, όπου N = forks.

```
Default forks = 5

Παράδειγμα: 12 hosts, Task 1: Install nginx

Batch 1 (παράλληλα):
┌──────┬──────┬──────┬──────┬──────┐
│ h-01 │ h-02 │ h-03 │ h-04 │ h-05 │  ← 5 hosts ταυτόχρονα
└──────┴──────┴──────┴──────┴──────┘
                 │
                 ▼ (ολοκλήρωση)
Batch 2 (παράλληλα):
┌──────┬──────┬──────┬──────┬──────┐
│ h-06 │ h-07 │ h-08 │ h-09 │ h-10 │  ← επόμενα 5
└──────┴──────┴──────┴──────┴──────┘
                 │
                 ▼
Batch 3:
┌──────┬──────┐
│ h-11 │ h-12 │  ← τελευταία 2
└──────┴──────┘
```

## Πόση ώρα παίρνει;

```
Παράδειγμα υπολογισμού:
- 100 hosts
- 10 tasks, 5 δευτερόλεπτα το καθένα
- Default forks = 5

Χωρίς παραλληλισμό (forks=1):
  100 hosts × 10 tasks × 5s = 5.000 δευτερόλεπτα (~83 λεπτά) ❌

Με forks=5 (default):
  (100/5) batches × 10 tasks × 5s = 1.000 δευτερόλεπτα (~17 λεπτά)

Με forks=20:
  (100/20) batches × 10 tasks × 5s = 250 δευτερόλεπτα (~4 λεπτά)

Με forks=50:
  (100/50) batches × 10 tasks × 5s = 100 δευτερόλεπτα (~2 λεπτά) ✅
```

> ⚠️ **Σημαντικό:** Περισσότερα forks = περισσότεροι πόροι στον **Ansible controller** (CPU, RAM, SSH connections). Δεν υπάρχει "άπειρα forks".

## Τα τρία "knobs" performance

```
Performance Toolkit
│
├── forks
│   └── «Πόσα hosts ταυτόχρονα;»
│       Default: 5 — Συνίσταται: 20-50
│
├── serial
│   └── «Rolling update — πόσα hosts ανά batch;»
│       Χρήση: Production deployments, zero downtime
│
├── async + poll
│   └── «Μην περιμένεις — τρέξε στο background»
│       Χρήση: Long-running tasks (backups, compiles)
│
└── strategy
    └── «Linear ή free execution;»
        Default: linear
        Επιλογή: free (κάθε host τελειώνει στη δική του ταχύτητα)
```

## SSH Connection Performance

Πέρα από τα forks, το SSH overhead είναι σημαντικός παράγοντας. Στο `ansible.cfg`:

```ini
[defaults]
# Αριθμός παράλληλων hosts
forks = 20

[ssh_connection]
# SSH multiplexing — επαναχρησιμοποίηση συνδέσεων
ssh_args = -o ControlMaster=auto -o ControlPersist=60s

# Pipeline — αποστολή modules χωρίς temp αρχεία
pipelining = true
```

> 💡 **Ποσοστό βελτίωσης:**
> ```
> Χωρίς pipelining:  ~~3 SSH connections~~ ανά task
> Με pipelining:     1 SSH connection ανά task → ~3x πιο γρήγορο!
> ```

## gather_facts — Ο «κρυφός» χρόνος

Η **συλλογή facts** (`gather_facts: true`) είναι συχνά το πιο αργό βήμα:

```
Παράδειγμα: 50 hosts, forks=10
gather_facts παίρνει ~3-5 δευτερόλεπτα ανά host

Συνολικός χρόνος gather_facts:
  (50/10) batches × 4s = 20 δευτερόλεπτα
  → Μόνο για facts! Πριν αρχίσουν τα tasks!
```

```yaml
---
- name: Playbook χωρίς facts (αν δεν χρειάζονται)
  hosts: all
  gather_facts: false    # ← παράλειψη → γρηγορότερο!

  tasks:
    - name: Simple command
      ansible.builtin.command:
        cmd: uptime
      changed_when: false
```

> ⚠️ **Προσοχή:** Αν χρησιμοποιείς `ansible_facts` στα tasks σου, **δεν** μπορείς να βάλεις `gather_facts: false`.

## Σύνοψη 18.1

```
Πώς εκτελεί η Ansible
│
├── Linear execution (default):
│   Task N → ολοκλήρωση σε ΟΛΟΥΣ → Task N+1
│
├── forks = N:
│   N hosts εκτελούν το ίδιο task ταυτόχρονα
│   Default: 5 — Τυπικό: 20-50
│
├── SSH overhead:
│   ├── pipelining = true → ~3x γρηγορότερο
│   └── ControlPersist → επαναχρησιμοποίηση connections
│
└── gather_facts:
    ├── Αργό για πολλά hosts
    └── gather_facts: false αν δεν χρειάζεται
```
