# 18.3 serial — Rolling Updates 🔄

## Τι είναι το serial

Το `serial` ελέγχει **πόσα hosts** εκτελούν ένα ολόκληρο **play** τη φορά — σε αντίθεση με τα `forks` που ελέγχουν πόσα hosts εκτελούν ένα **task**.

> 📝 **Η κρίσιμη διαφορά:**
> ```
> forks = 10:
>   Task 1 → 10 hosts παράλληλα → τελειώνει
>   Task 2 → 10 hosts παράλληλα → τελειώνει
>   ...
>
> serial = 2:
>   hosts 1-2 → Task 1, Task 2, Task 3 → τελειώνουν ΟΛΑ
>   hosts 3-4 → Task 1, Task 2, Task 3 → τελειώνουν ΟΛΑ
>   ...
>
> → Με serial: τα πρώτα 2 hosts ολοκληρώνουν ΟΛΟ
>   το play πριν αρχίσουν τα επόμενα 2!
> ```

---

## Γιατί χρειάζεται το serial

### Πρόβλημα χωρίς serial:

```
6 webservers πίσω από load balancer
Deploy νέα έκδοση εφαρμογής (forks=6):

Task 1: Stop service
┌──────┬──────┬──────┬──────┬──────┬──────┐
│ w-01 │ w-02 │ w-03 │ w-04 │ w-05 │ w-06 │  ← ΟΛΑ σταματούν!
└──────┴──────┴──────┴──────┴──────┴──────┘
          DOWNTIME! Ο load balancer δεν έχει κανέναν ❌
```

### Λύση με serial:

```
serial = 2 → Rolling update:

Batch 1: w-01, w-02
  Stop → Deploy → Start → Health check ✅

Batch 2: w-03, w-04         (w-01, w-02 servicing traffic)
  Stop → Deploy → Start → Health check ✅

Batch 3: w-05, w-06         (w-01-04 servicing traffic)
  Stop → Deploy → Start → Health check ✅

→ Πάντα 4+ servers σερβίρουν traffic = Zero Downtime ✅
```

## Σύνταξη serial

### Αριθμός hosts

```yaml
---
- name: Rolling Update
  hosts: webservers
  serial: 2          # ← 2 hosts ανά batch (απόλυτος αριθμός)
  become: true

  tasks:
    - name: Deploy new version
      # ...
```

### Ποσοστό hosts

```yaml
---
- name: Rolling Update
  hosts: webservers
  serial: "25%"      # ← 25% των hosts ανά batch
  become: true

  tasks:
    # ...
```

```
Παράδειγμα: 20 webservers, serial: "25%"

Batch 1: 5 hosts  (25% of 20)
Batch 2: 5 hosts
Batch 3: 5 hosts
Batch 4: 5 hosts
```

### Προοδευτικό (Canary) deployment

```yaml
---
- name: Canary Rolling Deployment
  hosts: webservers
  serial:            # ← λίστα τιμών!
    - 1              # Batch 1: 1 host (canary)
    - 2              # Batch 2: 2 hosts
    - "25%"          # Batch 3+: 25% κάθε φορά
  become: true

  tasks:
    # ...
```

```
Παράδειγμα: 20 webservers

Batch 1:  1 host   ← canary, περιμένεις, ελέγχεις
Batch 2:  2 hosts  ← επιβεβαίωση
Batch 3:  5 hosts  ← 25% of 20
Batch 4:  5 hosts
Batch 5:  5 hosts
Batch 6:  2 hosts  ← τελευταίοι

→ Σταδιακή αύξηση = μέγιστη ασφάλεια! ✅
```

## max_fail_percentage — Ασφαλιστική δικλίδα

Το `max_fail_percentage` σταματά το rolling update αν **πολλά hosts αποτύχουν**:

```yaml
---
- name: Rolling Update με Safety Net
  hosts: webservers
  serial:              "25%"
  max_fail_percentage: 20      # ← σταμάτα αν > 20% αποτύχουν

  tasks:
    - name: Deploy
      # ...
```

```
Παράδειγμα: 20 hosts, serial=5, max_fail_percentage=20%

Batch 1: 5 hosts
  - 4 επιτυχία, 1 αποτυχία = 20% failed
  - 20% <= max_fail_percentage (20%)
  → Συνέχεια ✅

Batch 2: 5 hosts
  - 3 επιτυχία, 2 αποτυχία = 40% failed
  - 40% > max_fail_percentage (20%)
  → ΣΤΑΜΑΤΑΕΙ! ❌
  → Τα υπόλοιπα hosts δεν αλλάζουν → rollback εύκολο!
```

> ⚠️ **Σημαντικό:** `max_fail_percentage: 0` σημαίνει «σταμάτα αν έστω κι ένα host αποτύχει».

## serial + pre_tasks / post_tasks — Drain & Restore

Ένα κλασικό pattern για zero-downtime:

```yaml
---
- name: Zero-Downtime Rolling Update
  hosts: webservers
  serial: "25%"
  max_fail_percentage: 0

  pre_tasks:

    # ── 1. Αφαίρεση από load balancer ──────────
    - name: Αφαίρεση από HAProxy
      community.general.haproxy:
        state:   disabled
        host:    "{{ inventory_hostname }}"
        backend: webservers_backend
        socket:  /var/run/haproxy.sock
        wait:    true        # ← περιμένει να τελειώσουν connections
      delegate_to: "{{ groups['loadbalancers'][0] }}"

    - name: Αναμονή για drain connections
      ansible.builtin.pause:
        seconds: 10
        prompt:  "Αναμονή για drain {{ inventory_hostname }}..."

  tasks:

    # ── 2. Deployment ────────────────────────────
    - name: Σταμάτα service
      ansible.builtin.service:
        name:  myapp
        state: stopped

    - name: Deploy νέα έκδοση
      ansible.builtin.copy:
        src:  "files/myapp-{{ app_version }}/"
        dest: /opt/myapp/
        mode: '0755'

    - name: Εκκίνηση service
      ansible.builtin.service:
        name:  myapp
        state: started

    # ── 3. Health check ──────────────────────────
    - name: Health check
      ansible.builtin.uri:
        url:         "http://localhost:8080/health"
        status_code: 200
      register: health
      retries:  10
      delay:    3
      until:    health.status == 200

  post_tasks:

    # ── 4. Επαναφορά στον load balancer ─────────
    - name: Επαναφορά στον HAProxy
      community.general.haproxy:
        state:   enabled
        host:    "{{ inventory_hostname }}"
        backend: webservers_backend
        socket:  /var/run/haproxy.sock
      delegate_to: "{{ groups['loadbalancers'][0] }}"

    - name: "✅ {{ inventory_hostname }} επανήλθε"
      ansible.builtin.debug:
        msg: "{{ inventory_hostname }} servicing traffic ξανά!"
```

## serial vs forks — Πίνακας σύγκρισης

```
┌───────────────────────────────────────────────────────────┐
│           serial                 │         forks           │
├───────────────────────────────────────────────────────────┤
│  Ελέγχει πόσα hosts              │  Ελέγχει πόσα hosts     │
│  εκτελούν ΟΛΟ το play            │  εκτελούν ΕΝΑ task      │
├───────────────────────────────────────────────────────────┤
│  Χρήση: Rolling updates,         │  Χρήση: Performance,    │
│  zero downtime                   │  ταχύτητα               │
├───────────────────────────────────────────────────────────┤
│  serial: 2 → 2 hosts ολοκλη-     │  forks: 20 → 20 hosts   │
│  ρώνουν πριν τα επόμενα          │  παράλληλα ανά task      │
├───────────────────────────────────────────────────────────┤
│  Αργότερο (ασφαλές)              │  Γρηγορότερο            │
└───────────────────────────────────────────────────────────┘
```

> 💡 **Μπορείς να τα συνδυάσεις:**
> ```yaml
> serial: 5     # 5 hosts εκτελούν ολόκληρο το play
> # + global forks = 20 → κάθε task εκτελείται
> #   και στα 5 hosts ταυτόχρονα (αλλά περιορίζεται στα 5)
> ```

## Σύνοψη 18.3

```
serial — Rolling Updates
│
├── Τι κάνει: N hosts εκτελούν ΟΛΟ το play
│            πριν αρχίσουν τα επόμενα N
│
├── Τιμές:
│   ├── serial: 2      → 2 hosts
│   ├── serial: "25%"  → 25% των hosts
│   └── serial: [1, 2, "25%"] → canary deployment
│
├── max_fail_percentage:
│   └── Σταμάτα αν X% αποτύχουν
│       0 = σταμάτα αν οποιοσδήποτε αποτύχει
│
├── Pattern: pre_tasks / post_tasks
│   ├── pre_tasks:  Drain from load balancer
│   └── post_tasks: Restore to load balancer
│
└── Vs forks:
    ├── serial → ασφάλεια (rolling)
    └── forks  → ταχύτητα (παράλληλα tasks)
```
