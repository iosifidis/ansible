# 18.4 async & poll — Long-running Tasks ⏳

## Το πρόβλημα

Μερικά tasks παίρνουν **πολλή ώρα** — backups, μεταγλωττίσεις, migrations. Κανονικά:

```
Task: Full system backup (15 λεπτά)

host-01 ──────────────────────── backup (15 min) ────────────► ✅
host-02 ──────────────────────── backup (15 min) ────────────► ✅
host-03 ──────────────────────── backup (15 min) ────────────► ✅

Σύνολο χρόνου: 15 λεπτά (με forks=3)
               → OK, αλλά η SSH σύνδεση κρατιέται ανοιχτή
                 για 15 λεπτά! Κίνδυνος timeout! ❌
```

---

## Η λύση: async + poll

```yaml
tasks:

  - name: Full system backup
    ansible.builtin.command:
      cmd: /opt/backup/full-backup.sh
    async: 3600       # ← max χρόνος αναμονής (seconds)
    poll:  30         # ← έλεγχος κατάστασης κάθε 30s
    changed_when: true
```

```
Πώς λειτουργεί:

Ansible → στέλνει εντολή στον host → κλείνει SSH ✅
             │
             ▼
Host εκτελεί backup στο background
             │
Ansible → ξανανοίγει SSH κάθε 30s ─────► "τελείωσε;"
             │                                │
             │                           ΟΧΙ → κλείνει, περιμένει 30s
             │                                │
             │                           ΝΑΙ → τέλος ✅
```

---

## async — Timeout

Το `async` ορίζει τον **μέγιστο χρόνο** (seconds) που μπορεί να τρέξει το task. Αν υπερβεί αυτόν → αποτυχία.

```yaml
tasks:

  # ── Βασική χρήση ──────────────────────────
  - name: Μεγάλο task με timeout
    ansible.builtin.command:
      cmd: /opt/long-process.sh
    async:        3600    # ← timeout: 1 ώρα (3600s)
    poll:         60      # ← έλεγχος κάθε 60s
    changed_when: true
```

> ⚠️ **Σημαντικό:** `async` δεν είναι ο χρόνος που **θα τρέξει** — είναι ο μέγιστος χρόνος που **επιτρέπεται**. Βάλε αρκετά μεγάλη τιμή.

---

## poll — Συχνότητα ελέγχου

Το `poll` ορίζει κάθε πόσα δευτερόλεπτα η Ansible **ελέγχει** αν τελείωσε το task.

```yaml
tasks:

  # ── poll: 0 → Fire-and-forget (χωρίς αναμονή!) ──
  - name: Εκκίνηση backup (no wait)
    ansible.builtin.command:
      cmd: /opt/backup/backup.sh
    async:        3600
    poll:         0       # ← ΔΕΝ περιμένει!
    changed_when: true    #   Συνεχίζει στο επόμενο task!

  # ── poll: 10 → Συχνός έλεγχος ──────────────
  - name: Γρήγορο task (5-30s)
    ansible.builtin.command:
      cmd: /opt/quick-task.sh
    async:        120
    poll:         10      # ← έλεγχος κάθε 10s

  # ── poll: 60 → Αραιός έλεγχος ──────────────
  - name: Πολύ αργό task (ώρες)
    ansible.builtin.command:
      cmd: /opt/very-slow-task.sh
    async:        86400   # ← 24 ώρες
    poll:         120     # ← έλεγχος κάθε 2 λεπτά
    changed_when: true
```

---

## Fire-and-Forget Pattern (poll: 0)

Με `poll: 0` η Ansible **δεν περιμένει** το αποτέλεσμα. Είναι ιδανικό για tasks που θέλεις να τρέξουν παράλληλα:

```yaml
tasks:

  # ── Εκκίνηση πολλών tasks ταυτόχρονα ───────
  - name: "Backup host-01 (background)"
    ansible.builtin.command:
      cmd: /opt/backup.sh --target host-01
    async:        3600
    poll:         0
    register:     backup_h01
    changed_when: true

  - name: "Backup host-02 (background)"
    ansible.builtin.command:
      cmd: /opt/backup.sh --target host-02
    async:        3600
    poll:         0
    register:     backup_h02
    changed_when: true

  - name: "Backup host-03 (background)"
    ansible.builtin.command:
      cmd: /opt/backup.sh --target host-03
    async:        3600
    poll:         0
    register:     backup_h03
    changed_when: true

  # ── Κάνε άλλες δουλειές στο μεταξύ ─────────
  - name: Update package cache (ενώ τρέχουν backups)
    ansible.builtin.apt:
      update_cache: true

  # ── Τώρα περίμενε τα backups ─────────────────
  - name: "Αναμονή για backup host-01"
    ansible.builtin.async_status:
      jid: "{{ backup_h01.ansible_job_id }}"
    register: job_result
    until:    job_result.finished
    retries:  60
    delay:    30

  - name: "Αναμονή για backup host-02"
    ansible.builtin.async_status:
      jid: "{{ backup_h02.ansible_job_id }}"
    register: job_result
    until:    job_result.finished
    retries:  60
    delay:    30

  - name: "Αναμονή για backup host-03"
    ansible.builtin.async_status:
      jid: "{{ backup_h03.ansible_job_id }}"
    register: job_result
    until:    job_result.finished
    retries:  60
    delay:    30
```

## async_status — Επαλήθευση αποτελέσματος

Το `ansible.builtin.async_status` ελέγχει την κατάσταση ενός async job:

```yaml
tasks:

  # ── Εκκίνηση async task ─────────────────────
  - name: Compilation
    ansible.builtin.command:
      cmd: make -j4 all
      chdir: /opt/myapp/src
    async:        1800    # ← 30 λεπτά
    poll:         0       # ← fire and forget
    register:     compile_job
    changed_when: true

  # ── Άλλα tasks στο μεταξύ ───────────────────
  - name: Εγκατάσταση dependencies
    ansible.builtin.apt:
      name:
        - nginx
        - postgresql
      state: present

  # ── Έλεγχος αποτελέσματος compilation ───────
  - name: Αναμονή για compilation
    ansible.builtin.async_status:
      jid: "{{ compile_job.ansible_job_id }}"
    register: compile_result
    until:    compile_result.finished
    retries:  36          # ← 36 × 30s = 18 λεπτά max αναμονή
    delay:    30

  - name: Αποτέλεσμα compilation
    ansible.builtin.debug:
      msg: >
        Compilation:
        {{ '✅ Επιτυχής' if compile_result.rc == 0
                        else '❌ Αποτυχία' }}
```

## Πότε να χρησιμοποιείς async

```
Χρησιμοποίησε async:
✅ Tasks που διαρκούν > 30-60 δευτερόλεπτα
   (κίνδυνος SSH timeout)

✅ Backups μεγάλων αρχείων

✅ Package installations σε αργά συστήματα
   (π.χ. Raspberry Pi)

✅ Database migrations

✅ Μεταγλωττίσεις (make, gradle, mvn)

✅ Tasks που θέλεις να τρέξουν παράλληλα
   (poll: 0 + async_status)

ΜΗΝ χρησιμοποιείς async:
❌ Tasks που χρειάζονται το αποτέλεσμα αμέσως
❌ Tasks με notify (handlers δεν ενεργοποιούνται!)
❌ Απλά tasks < 30 δευτερόλεπτα
```

> ⚠️ **Σημαντικό:** Τα `notify` (handlers) **δεν λειτουργούν** με async tasks. Αν χρειάζεσαι handler, χρησιμοποίησε `meta: flush_handlers` μετά τον έλεγχο με `async_status`.

## Πρακτικό παράδειγμα — Παράλληλα backups

```yaml
---
# parallel-backups.yml

- name: Παράλληλα Backups με Async
  hosts: all
  gather_facts: true

  vars:
    backup_timeout: 3600   # 1 ώρα
    backup_script:  /opt/backup/backup.sh
    backup_dir:     /var/backups/ansible

  tasks:

    # ── Προετοιμασία ──────────────────────────
    - name: Δημιουργία backup directory
      ansible.builtin.file:
        path:  "{{ backup_dir }}"
        state: directory
        mode:  '0750'

    # ── Εκκίνηση backup (παράλληλα, no wait) ──
    - name: "🚀 Έναρξη backup {{ inventory_hostname }}"
      ansible.builtin.command:
        cmd: >
          {{ backup_script }}
          --output {{ backup_dir }}/{{ inventory_hostname }}-{{ ansible_date_time.date }}.tar.gz
          --compress gzip
          --exclude /proc --exclude /sys --exclude /tmp
      async:        "{{ backup_timeout }}"
      poll:         0       # ← fire-and-forget
      register:     backup_job
      changed_when: true

    # ── Αναφορά εκκίνησης ─────────────────────
    - name: Backup ξεκίνησε
      ansible.builtin.debug:
        msg: >
          {{ inventory_hostname }}:
          Job ID: {{ backup_job.ansible_job_id }}
          (τρέχει στο background...)

    # ── Άλλες εργασίες στο μεταξύ ────────────
    - name: "📊 Συλλογή disk info (ενώ τρέχει backup)"
      ansible.builtin.shell:
        cmd: "df -h | grep -v tmpfs"
      register:     disk_info
      changed_when: false

    - name: Disk usage
      ansible.builtin.debug:
        msg: "{{ disk_info.stdout_lines }}"
        verbosity: 1

    # ── Αναμονή για backup ─────────────────────
    - name: "⏳ Αναμονή για backup {{ inventory_hostname }}"
      ansible.builtin.async_status:
        jid: "{{ backup_job.ansible_job_id }}"
      register: backup_result
      until:    backup_result.finished
      retries:  120         # ← 120 × 30s = 1 ώρα max
      delay:    30

    # ── Αποτέλεσμα ────────────────────────────
    - name: Αποτέλεσμα backup
      ansible.builtin.debug:
        msg:
          - "Host   : {{ inventory_hostname }}"
          - "Status : {{ '✅ Επιτυχής' if backup_result.rc == 0 else '❌ Αποτυχία' }}"
          - "RC     : {{ backup_result.rc }}"

    # ── Αποτυχία αν το backup απέτυχε ─────────
    - name: Έλεγχος επιτυχίας backup
      ansible.builtin.assert:
        that:
          - backup_result.rc == 0
        fail_msg:    "❌ Backup απέτυχε για {{ inventory_hostname }}!"
        success_msg: "✅ Backup επιτυχές για {{ inventory_hostname }}!"
```

```bash
# Εκτέλεση — ΟΛΑ τα backups τρέχουν ταυτόχρονα!
ansible-playbook playbooks/parallel-backups.yml \
    -f 50 -v

# Παρακολούθηση χωρίς αναμονή (fire-and-forget)
ansible-playbook playbooks/parallel-backups.yml \
    --limit all
```

## Σύνοψη 18.4

```
async & poll
│
├── async: N → Max χρόνος εκτέλεσης (seconds)
│   └── Αν υπερβεί: αποτυχία
│
├── poll: N → Έλεγχος κάθε N seconds
│   ├── poll: 0  → Fire-and-forget (no wait)
│   ├── poll: 10 → Συχνός έλεγχος (γρήγορα tasks)
│   └── poll: 60 → Αραιός έλεγχος (αργά tasks)
│
├── async_status module:
│   └── Χειροκίνητος έλεγχος async job
│       jid: "{{ job.ansible_job_id }}"
│
├── Χρήση:
│   ✅ Tasks > 30-60 δευτερόλεπτα
│   ✅ Παράλληλη εκτέλεση (poll: 0)
│   ❌ Tasks με notify (handlers)
│
└── Pattern: fire-and-forget
    ├── Task 1: async, poll: 0, register: job1
    ├── Task 2: async, poll: 0, register: job2
    ├── (άλλα tasks στο μεταξύ)
    └── async_status: jid: job1, job2
```
