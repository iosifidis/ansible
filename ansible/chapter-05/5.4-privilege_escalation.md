# 5.4 Section [privilege_escalation] 🔐

## Τι είναι το Privilege Escalation;

Το **Privilege Escalation** είναι η διαδικασία με την οποία η Ansible **αποκτά υψηλότερα δικαιώματα** στους remote servers — συνήθως από έναν κανονικό χρήστη σε `root`.

```
ansible user (συνδέεται)
      │
      │ sudo / su / pbrun
      ▼
root (εκτελεί tasks που χρειάζονται δικαιώματα)
```

> 📝 **Γιατί χρειάζεται;** Η Ansible συνδέεται ως `ansible` user (όχι root για ασφάλεια), αλλά πολλές εργασίες (εγκατάσταση packages, ρύθμιση services κλπ) χρειάζονται `root` δικαιώματα.

---

## Οι ρυθμίσεις

```ini
[privilege_escalation]

# Ενεργοποίηση privilege escalation
# Default: False
# True → η Ansible χρησιμοποιεί sudo/su αυτόματα
become = true

# Μέθοδος escalation
# Default: sudo
# Επιλογές: sudo, su, pbrun, pfexec, doas, dzdo, ksu
become_method = sudo

# Ποιος χρήστης θα γίνει μετά το escalation
# Default: root
become_user = root

# Να ζητάει password για sudo;
# Default: False
# True  → ζητάει password (πιο ασφαλές)
# False → δεν ζητάει (χρειάζεται NOPASSWD στο sudoers)
become_ask_pass = false
```

## Οι μέθοδοι Escalation

```
┌─────────────────────────────────────────────────────────┐
│ Μέθοδος  │ Πότε Χρησιμοποιείται                         │
├──────────┼──────────────────────────────────────────────┤
│ sudo     │ Linux/Unix (default) ✅                      │
│ su       │ Παλιά συστήματα χωρίς sudo                   │
│ pbrun    │ PowerBroker environments                     │
│ pfexec   │ Solaris                                      │
│ doas     │ OpenBSD                                      │
│ dzdo     │ Centrify                                     │
│ ksu      │ Kerberos                                     │
└─────────────────────────────────────────────────────────┘
```

> 💡 **Στην πράξη:** Σχεδόν πάντα χρησιμοποιούμε `sudo`. Οι άλλες μέθοδοι είναι για ειδικά εταιρικά περιβάλλοντα.

---

## Σχέση με το Sudoers

Για να δουλεύει το `become_ask_pass = false`, πρέπει ο `ansible` user να έχει **NOPASSWD** στο sudoers:

```bash
# Στον managed server
cat /etc/sudoers.d/ansible
# ansible ALL=(ALL) NOPASSWD: ALL ✅
```

```
┌─────────────────────────────────────────────────────────┐
│  become_ask_pass = false  +  NOPASSWD στο sudoers       │
│  → Πλήρως αυτόματο, δεν ζητάει ποτέ password ✅         │
├─────────────────────────────────────────────────────────┤
│  become_ask_pass = true   +  κανονικό sudo              │
│  → Ζητάει password (πιο ασφαλές, λιγότερο αυτόματο)     │
├─────────────────────────────────────────────────────────┤
│  become_ask_pass = false  +  κανονικό sudo              │
│  → ΑΠΟΤΥΧΙΑ! Δεν μπορεί να γίνει sudo ❌                │
└─────────────────────────────────────────────────────────┘
```

## Override ανά Play ή Task

Οι ρυθμίσεις του `ansible.cfg` είναι **global defaults** — μπορείς να τις κάνεις override:

### Σε επίπεδο Play:
```yaml
- name: Play χωρίς sudo
  hosts: webservers
  become: false          # ← override του global true
  tasks:
    - name: Απλή εντολή (δεν χρειάζεται root)
      ansible.builtin.command: whoami

- name: Play με διαφορετικό user
  hosts: dbservers
  become: true
  become_user: postgres  # ← γίνε postgres αντί για root!
  tasks:
    - name: Database εργασία
      ansible.builtin.command: psql -l
```

### Σε επίπεδο Task:
```yaml
- name: Mixed permissions play
  hosts: all
  become: true           # ← default για όλο το play

  tasks:
    - name: Αυτό τρέχει ως root (κληρονομεί το play)
      ansible.builtin.package:
        name: nginx
        state: present

    - name: Αυτό τρέχει ως ansible (override)
      ansible.builtin.command: whoami
      become: false      # ← override για αυτό το task μόνο

    - name: Αυτό τρέχει ως www-data (override user)
      ansible.builtin.file:
        path: /var/www/html/index.html
        state: touch
      become: true
      become_user: www-data   # ← διαφορετικός user
```

## Become με Command Line

```bash
# Override become από command line
ansible-playbook playbooks/my_playbook.yml --become
ansible-playbook playbooks/my_playbook.yml -b        # ← σύντομη μορφή

# Override become_user
ansible-playbook playbooks/my_playbook.yml \
    --become \
    --become-user postgres

# Ζήτα password για sudo
ansible-playbook playbooks/my_playbook.yml \
    --become \
    --ask-become-pass
# ή
ansible-playbook playbooks/my_playbook.yml -b -K    # ← σύντομη μορφή
```

## Ασφάλεια & βέλτιστες πρακτικές

```
┌─────────────────────────────────────────────────────────┐
│  ✅ ΣΩΣΤΟ                                               │
│  ├── ansible user συνδέεται με SSH key (όχι password)   │
│  ├── NOPASSWD μόνο για τον ansible user                 │
│  ├── become = true μόνο όπου χρειάζεται                 │
│  └── become_user = συγκεκριμένος user (όχι πάντα root)  │
├─────────────────────────────────────────────────────────┤
│  ❌ ΛΑΘΟΣ                                               │
│  ├── Σύνδεση απευθείας ως root                          │
│  ├── NOPASSWD για όλους τους χρήστες                    │
│  ├── become = true παντού χωρίς λόγο                    │
│  └── Αποθήκευση passwords σε plaintext                  │
└─────────────────────────────────────────────────────────┘
```

## Πλήρες παράδειγμα [privilege_escalation]

```ini
[privilege_escalation]
# ── Βασικές ρυθμίσεις ────────────────────────
become          = true
become_method   = sudo
become_user     = root
become_ask_pass = false
```

> 📝 **Σημείωση:** Το `[privilege_escalation]` είναι συνήθως **πολύ απλό** — 4 γραμμές αρκούν. Η πολυπλοκότητα έρχεται από τα overrides στα playbooks.

---

## Σύνοψη 5.4

```
[privilege_escalation]
├── become          → ενεργοποίηση sudo (true/false)
├── become_method   → sudo (default), su, doas κλπ
├── become_user     → root (default) ή άλλος user
├── become_ask_pass → false (με NOPASSWD) ή true
└── Override:
    ├── Σε play level  → become: false/true
    ├── Σε task level  → become: false, become_user: postgres
    └── Command line   → -b, --become-user, -K
```
