# 26.1 Τι είναι το AWX / Ansible Automation Platform 🖥️

## Το πρόβλημα με το command line

```
Πρόβλημα με ansible-playbook στη γραμμή εντολών:

  ├── Μόνο ο sysadmin ξέρει τις εντολές
  ├── Δεν υπάρχει audit log "ποιος έτρεξε τι"
  ├── Δεν υπάρχει RBAC (role-based access control)
  ├── Δεν υπάρχει scheduling
  └── Δεν μπορεί ο junior να κάνει deploy μόνος του

Λύση: AWX / Ansible Automation Platform
```

---

## AWX vs Tower vs AAP

```
┌─────────────────────────────────────────────────────┐
│                                                     │
│  AWX                                                │
│  ├── Open source (GitHub)                           │
│  ├── Free                                           │
│  ├── Community support                              │
│  └── Upstream project (bleeding edge)               │
│                                                     │
│  Red Hat Ansible Tower (παλιό)                      │
│  ├── Enterprise product (πληρωμένο)                 │
│  └── Αντικαταστάθηκε από AAP                        │
│                                                     │
│  Red Hat Ansible Automation Platform (AAP)          │
│  ├── Enterprise product                             │
│  ├── Subscription-based                             │
│  ├── Automation Controller (= Tower)                │
│  ├── Automation Hub (private Galaxy)                │
│  └── Event-Driven Ansible                           │
│                                                     │
│  Για εκπαίδευση/homelab: AWX ✅                     │
│  Για production enterprise: AAP                     │
└─────────────────────────────────────────────────────┘
```

## Βασικές έννοιες AWX

```
AWX Οντότητες:
│
├── Organizations       → Διαχωρισμός ομάδων
├── Users               → Λογαριασμοί
├── Teams               → Ομάδες users
│
├── Credentials         → SSH keys, passwords, tokens
│                         (κρυπτογραφημένα!)
│
├── Projects            → Git repositories με playbooks
│
├── Inventories         → Hosts & groups
│   └── Sources         → Dynamic inventory plugins
│
├── Job Templates       → "Εκτελέσιμα" playbooks
│   ├── Project         → ποιο git repo
│   ├── Inventory       → ποιοι hosts
│   ├── Credentials     → ποιο SSH key
│   ├── Playbook        → ποιο .yml
│   └── Survey          → παράμετροι από user
│
├── Workflows           → Chains από Job Templates
│
├── Jobs                → Εκτελέσεις (με logs!)
│
└── Schedules           → Χρονοπρογραμματισμός
```

---

## Γιατί AWX για production;

```
AWX δίνει:
│
├── 👥 RBAC:
│   └── "Alice μπορεί να κάνει deploy μόνο
│         στους staging servers, όχι production"
│
├── 📋 Audit log:
│   └── "Στις 14:32 ο Bob έτρεξε deploy.yml
│         στον nextcloud — changed=5, failed=0"
│
├── ⏰ Scheduling:
│   └── "Κάθε Κυριακή 02:00 → patching.yml"
│
├── 📊 Dashboard:
│   └── Job history, success/failure rates
│
├── 🔗 API:
│   └── Ενεργοποίηση jobs από GitHub webhooks,
│         CI/CD pipelines, κ.ά.
│
└── 📝 Survey:
    └── "Ποια έκδοση να κάνεις deploy;"
         → Input form για non-technical users
```

---

## Σύνοψη 26.1

```
AWX / AAP
│
├── AWX = Open source Ansible web UI
├── AAP = Enterprise (Red Hat, subscription)
│
├── Λύνει:
│   ├── RBAC (ποιος κάνει τι)
│   ├── Audit (log ιστορικό)
│   ├── Scheduling (χρονοπρογραμματισμός)
│   └── API (webhook triggers)
│
└── Για homelab/εκπαίδευση: AWX (free)
```
