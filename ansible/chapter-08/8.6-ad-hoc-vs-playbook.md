# 8.6 Πότε Ad-Hoc vs Playbook 🤔

## Η βασική αρχή

```
┌─────────────────────────────────────────────────────────┐
│  Ad-Hoc  → "Κάνε ΑΥΤΟ τώρα"                             │
│  Playbook → "Κάνε ΑΥΤΑ με αυτή τη σειρά, πάντα"         │
└─────────────────────────────────────────────────────────┘
```

---

## Σύγκριση

```
┌─────────────────────┬──────────────┬────────────────────┐
│ Κριτήριο            │ Ad-Hoc       │ Playbook           │
├─────────────────────┼──────────────┼────────────────────┤
│ Ταχύτητα γραψίματος │ ⭐⭐⭐⭐⭐   │ ⭐⭐              │
│ Επαναχρησιμοποίηση  │ ❌           │ ✅                 │
│ Documentation       │ ❌           │ ✅                 │
│ Error handling      │ ❌           │ ✅                 │
│ Πολύπλοκη λογική    │ ❌           │ ✅                 │
│ Version control     │ ❌           │ ✅                 │
│ Audit trail         │ ⚠️           │ ✅                 │
│ Conditionals/loops  │ ❌           │ ✅                 │
│ Handlers            │ ❌           │ ✅                 │
└─────────────────────┴──────────────┴────────────────────┘
```

---

## Χρησιμοποίησε Ad-Hoc όταν...

```bash
# ✅ 1. Γρήγορος έλεγχος κατάστασης
ansible all -m ansible.builtin.ping
ansible all -m ansible.builtin.command -a "uptime"
ansible all -m ansible.builtin.command -a "df -h"

# ✅ 2. Μεμονωμένη εργασία μία φορά
ansible nextcloud -m ansible.builtin.service \
    -a "name=nginx state=restarted" --become

# ✅ 3. Emergency fix
ansible all -m ansible.builtin.shell \
    -a "kill -9 $(cat /var/run/zombie.pid)" --become

# ✅ 4. Συλλογή πληροφοριών
ansible all -m ansible.builtin.setup \
    -a "filter=ansible_memory_mb"

# ✅ 5. Test module πριν το βάλεις σε playbook
ansible nextcloud -m ansible.builtin.copy \
    -a "src=files/test.conf dest=/tmp/test.conf"

# ✅ 6. Γρήγορο deploy σε emergency
ansible nextcloud -m ansible.builtin.copy \
    -a "src=hotfix.py dest=/var/www/app/hotfix.py"
```

---

## Χρησιμοποίησε Playbook όταν...

```yaml
# ✅ 1. Επαναλαμβανόμενη εργασία
# security-bootstrap.yml → τρέχεις σε κάθε νέο server

# ✅ 2. Πολλά βήματα με σειρά
- name: Deploy Application
  tasks:
    - name: Stop service
    - name: Backup current version
    - name: Deploy new version
    - name: Run migrations
    - name: Start service
    - name: Verify deployment

# ✅ 3. Conditionals & loops
- name: Install packages
  ansible.builtin.package:
    name: "{{ item }}"
    state: present
  loop: "{{ common_packages }}"
  when: ansible_facts['os_family'] == "Debian"

# ✅ 4. Error handling
- name: Risky task
  block:
    - name: Try this
      ansible.builtin.command: /usr/bin/risky_script
  rescue:
    - name: Αν αποτύχει → rollback
      ansible.builtin.command: /usr/bin/rollback
  always:
    - name: Πάντα καθάρισε
      ansible.builtin.file:
        path: /tmp/tempfiles
        state: absent

# ✅ 5. Documentation μέσω ονομάτων
- name: "Εγκατάσταση nginx web server"
- name: "Ρύθμιση SSL certificates"
- name: "Ενεργοποίηση nginx service"
```

## Real-World παραδείγματα

### Σενάριο 1: Server Down!
```bash
# Ad-Hoc → γρήγορη αντίδραση!

# Ποιος server δεν ανταποκρίνεται;
ansible all -m ansible.builtin.ping

# Τι τρέχει;
ansible problematic_server -m ansible.builtin.shell \
    -a "ps aux | head -20" --become

# Restart service
ansible problematic_server -m ansible.builtin.service \
    -a "name=nginx state=restarted" --become

# Έλεγχος logs
ansible problematic_server -m ansible.builtin.shell \
    -a "tail -50 /var/log/nginx/error.log" --become
```

### Σενάριο 2: Νέος Server
```bash
# Playbook → επαναλήψιμη διαδικασία

# 1. Deploy SSH key (ad-hoc, μία φορά)
ssh-copy-id -i ~/.ssh/id_ed25519.pub \
    -p 22 debian@NEW_SERVER_IP

# 2. Security bootstrap (playbook)
ansible-playbook playbooks/security-bootstrap.yml \
    --limit new_server

# 3. Base configuration (playbook)
ansible-playbook playbooks/base-setup.yml \
    --limit new_server
```

### Σενάριο 3: Security Update
```bash
# Hybrid approach:

# Ad-hoc → έλεγχος πριν
ansible all -m ansible.builtin.shell \
    -a "apt list --upgradable 2>/dev/null | grep security" \
    --become

# Playbook → η ίδια η ενημέρωση
ansible-playbook playbooks/security-update.yml

# Ad-hoc → επαλήθευση μετά
ansible all -m ansible.builtin.command \
    -a "uptime" --become
```

## Workflow — Πώς δουλεύουν μαζί

```
┌─────────────────────────────────────────────────────────┐
│                                                         │
│  1. Ανακαλύπτεις τι χρειάζεσαι (Ad-Hoc)                 │
│     ansible nextcloud -m apt -a "name=nginx ..."        │
│                    ↓                                    │
│  2. Γράφεις Playbook (μόνιμη λύση)                      │
│     nano playbooks/install-nginx.yml                    │
│                    ↓                                    │
│  3. Test playbook (Ad-Hoc style)                        │
│     ansible-playbook ... --check --limit nextcloud      │
│                    ↓                                    │
│  4. Εκτέλεση Playbook                                   │
│     ansible-playbook playbooks/install-nginx.yml        │
│                    ↓                                    │
│  5. Επαλήθευση (Ad-Hoc)                                 │
│     ansible all -m service_facts | grep nginx           │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

## Σύνοψη 8.6

```
Ad-Hoc vs Playbook
├── Ad-Hoc:
│   ✅ Γρήγορα, μία φορά, έλεγχοι, emergency
│   ❌ Επανάληψη, λογική, error handling
│
├── Playbook:
│   ✅ Επανάληψη, documentation, λογική
│   ❌ Γρήγορη αντίδραση
│
├── Χρυσή Αρχή:
│   "Μία φορά → Ad-Hoc"
│   "Ξανά ή θέλεις να θυμάσαι → Playbook"
│
└── Workflow:
    Ad-Hoc (test) → Playbook (μόνιμο) → Ad-Hoc (verify)
```
